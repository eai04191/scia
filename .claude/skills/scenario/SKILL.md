# 初めて使う人として触らせる

準備と1人分の実行は`Tools/scenario/`のスクリプトが行う。このskillは、それを順に走らせ、報告を読んで確かめ、まとめてユーザーに渡す。外へ出ないMastodon（`mastodon.localhost`）と専用の端末`Scia Scenario`を使うので、`Scia 1`〜`Scia 4`は借りない。

引数（`$ARGUMENTS`）で、走らせる役を決める。役は`Tools/scenario/personas/`の、`common.md`以外のファイルの名前（`literal`、`impatient`、`breaker`）。1人ごとに`claude -p`で利用枠を使う。

- `*`なら、全部の役を走らせる
- 役の名前が空白区切りで入っていれば、それだけを走らせる
- 引数がなければ、準備に入る前に、どの役を走らせるかを質問のツールで聞く。役ごとに選択肢を作り（複数選べるようにする）、説明には役のファイルの人となりを短く書く

## 1. 準備する

- Docker（OrbStack）が動いていて、`axe`が入っていることを確かめる。Dockerが動いていなければ、起動を頼んで止まる。`axe`がなければ、`brew install cameroncooke/axe/axe`で入れるよう頼んで止まる
- `make scenario-setup`を走らせる。何度走らせても同じ状態になり、足りないものだけを作る。スナップショットを作り直すときは数分かかる
- `make scenario-setup`と次の`make scenario-run`は、ユーザーの指示にある待ち方（バックグラウンドで起動し、終了コードのファイルを同じターンのうちにフォアグラウンドで待つ）で走らせる

## 2. 役ごとに走らせる

- 端末は1台なので、役を1つずつ順に走らせる: `make scenario-run PERSONA=<役>`
- 1人分は数分から十数分かかる。最後の行に、報告の場所（`~/scia-scenario/runs/<日時>-<役>/report.md`）が出る
- 失敗で終わったら、まずコマンドの出力で、どこで止まったかを確かめる。リセットの段（Dockerが止まった、端末が起動しないなど）で止まったときは、実行のフォルダーも`result.json`もまだない。直して走らせ直す
- 「役「<役>」で触らせる」のあとで止まったときだけ、そのフォルダーの`result.json`を読む。エージェントが途中で止まっただけなら、その役は「最後まで走らなかった」として、残った報告を使う

## 3. 報告を確かめる

エージェントの報告は、そのまま信じない。詰まったところごとに、書かれたスクリーンショットをReadで開き、書いてあることが画面に出ているかを確かめる。次のどれかに分ける。

- Sciaの問題: 画面で確かめられた
- 道具の問題: AXeやシミュレーターの操作のしかたで起きたもの（タップが届かない、打った文字が入らない、座標の取り違えなど）。Sciaの問題には数えない
- 確かめられない: スクリーンショットがない、画面と食い違う

あわせて、意図した作りかどうかがSciaのコードやdocs（`docs/`）から分かるものは、その旨を添える。たとえば、操作を長押しのメニューに置く作りなら、「入口が見つからない」は「見つけにくい」として扱い、不具合とは書かない。

## 4. まとめて渡す

- 同じ問題を、役をまたいで1つにまとめ、当たった役の数が多い順、同じなら困った度合いが大きい順に並べる
- 項目ごとに、何が起きたか、当たった役、困った度合い、スクリーンショットの絶対パス、意図した作りかどうか（分かれば）を書く
- 代表的なスクリーンショットをSendUserFileで添える
- 道具の問題と確かめられないものは、最後に短くまとめる
- 前に同じ役で走らせた報告が`~/scia-scenario/runs/`にあれば、前回の項目ごとに、今回どうだったかを次のどれかで書き、今回新しく出たものも分けて書く。直したあとの確かめでは、これを主に書く
  - 消えた: 今回の報告とスクリーンショットで、同じ操作をして、問題が起きなかったことを確かめられた
  - 残っている: 今回も同じ問題が出た
  - 確かめていない: 今回の報告にないが、同じ操作をしたかが分からない、または役が途中で止まった。報告にないだけで「消えた」としない。消えたかを確かめたいときは、その操作を名指しした役で走らせ直すか、ユーザーに聞く
- 直すかどうか、どれから直すかはユーザーが決める。このskillでは直さない。決めてもらうときは、項目に識別子を付けて質問のツールで聞く
- 終わったら、Mastodonは動かしたままにしてよい。`Scia Scenario`は`make scenario-run`が止める
