# シミュレーターの割り当て

どのスレッドがどの端末を使っているかは、sciaのスレッドのタイトルの先頭の番号で表す（例: 「2オブジェクトタップのプライマリアクション設定」は`Scia 2`を使っている）。割り当ての記録をほかに持たないので、スレッドをアーカイブすれば端末も空く。

引数（`$ARGUMENTS`）には、使う端末の番号（1〜4）が入ることがある。

## 1. このスレッドの端末が決まっていないかを確かめる

`mcp__ccd_session_mgmt__get_session`に`self`を渡し、このスレッドのタイトルを読む。

- タイトルの先頭が番号で、引数がないか同じ番号なら、その端末が割り当て済み。ただし、このスレッドが止まっている間に、ほかのスレッドがその番号を指定して重ねていることがある。2の一覧で、その番号を使うほかのスレッドが動いていないかだけを確かめ、動いていなければ4へ進む。設定は戻さない。同じスレッドが前に変えた設定を、確かめの途中で消さないため。動いていれば、2の「番号を指定されたとき」と同じく止める
- 引数で別の番号を指定されたら、2へ進み、タイトルの番号を付け替える

## 2. 番号を選ぶ

`mcp__ccd_session_mgmt__list_sessions`（`limit`は200）で、アーカイブしていないスレッドを読む。ほかのプロジェクトのスレッドも含むので、返った件数が`limit`と同じなら、読み切れていない番号を空きと取り違えるおそれがある。割り当てを止めて、ユーザーに古いスレッドのアーカイブを頼む。sciaのスレッドは、`cwd`が`git rev-parse --path-format=absolute --git-common-dir`の親（元のcheckout）か、その下の`.claude/worktrees/`の中にあるもの。そのうち、タイトルの先頭が1〜4の1文字で、その次が数字でないものを、その番号の端末を使っているスレッドとする。

- 番号を指定されたとき
  - その番号を使うスレッドが動いている（`isRunning`）なら、取り合いになるので止める。そのスレッドを`[タイトル](#<sessionId>)`で示し、ユーザーにどうするか聞く
  - 止まっているスレッドだけが使っているなら、ユーザーが意図して重ねたものとして取る。報告で、同じ端末を使うスレッドを示す
- 番号を指定されていないとき
  - どのスレッドも使っていない番号のうち、一番小さいものを取る
  - 空きがなければ、止まっているスレッドの端末を勝手に取らない。使っているスレッドを番号ごとに示し、どの端末に重ねるかをユーザーに聞く。重ねるかどうかはユーザーが決める

## 3. タイトルに番号を付け、設定を戻す

- `mcp__ccd_session_mgmt__set_session_title`に`self`と、タイトルの先頭に番号を付けたものを渡す。番号とタイトルの間は空けない（例: 「3シミュレータアプリ設定の初期化」）。前に別の番号が付いていたら、付け替える。ユーザーがタイトルを付けていると、アプリが承認を求める
- 2つのスレッドが同時に一覧を読むと、同じ空き番号を選ぶことがある。タイトルを変えたら一覧を読み直し、同じ番号のほかのスレッドが新しく現れていたら、`sessionId`を文字列で比べて大きいほうが譲る。譲るときは、その番号を使うスレッドとして数え直して2から選び直す。小さいほうは、そのまま進む
- 新しく割り当てたときは、`Tools/sim.sh reset 'Scia <番号>'`で、アプリを終了し、アプリの設定（設定、チューニング、デバッグ用の値）を既定に戻す。前に使ったスレッドが確かめのために変えた値を持ち込まないため。ログイン情報とアカウントの並びは残る

## 4. 伝える

使う端末を1行で伝える（例: 「`Scia 3`を使います。設定を既定に戻しました」）。重ねたときは、同じ端末を使うスレッドも示す。以後、シミュレーターのツールの`device`、`make test`の`SIM`、`Tools/sim.sh`には、この端末を渡す。
