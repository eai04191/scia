# 絵文字パレットの紹介動画のspec

このbranchでやったことを、Mastodonに投稿する動画で伝える。

## 伝えること

1. 今までの絵文字パレットは、開いたときやゆっくり流すときは問題ないが、速く流すと表示が追いつかず空白ができた
2. 新しい絵文字パレットは、速く流しても全部見える
3. どう解決したか（仕組み）

mainを過剰に悪く見せない。開くとパパッと読み込まれて一見問題ない → しゃっと速く流すと追いつかない、を見せるのが重要。

## 形式

- 1080×1080、60fps、音なし
- ライトテーマだけを作る。色は実物のSciaのライトモードから取る（地#F2F2F7、強調は送信ボタンの青#0088FF）。アイコンは本物のSF Symbolsを使う
- Mastodonでループする前提。最後はロゴを約3秒見せ、最初のコマへ自然につなぐ
- アイコンは、アプリのアイコン（Liquid Glass）をIcon Composerの`ictool`で書き出したものを使う
- コードだけで描く。`render(t)`は時刻だけから描く。60fps×4サブフレームを書き出し、ffmpegの`tmix`でモーションブラーをかける
- 見出しは、文字の量に合わせて十分な時間出す。寄る場面の見出しは、1文字0.12秒＋1秒にする
- 見出しを改行するところには、読点を置かない（「空きが少なければ<改行>元の絵は残しません」）

## 配置

- ロゴは下に置き、暗いバー（高さ84px、#1C1C1E）の左に、アプリのアイコンと白い「Scia」を置く。中身はバーの分だけ上へずらす
- 左右の余白は、見出し、入力欄、絵文字パレット、ロゴ、仕組みの図のすべてで96px
- 間隔は、見出しの枠ではなく、実際に見える文字の上下の端で測る
- 見出しと入力欄のあいだは40px。外側の余白（画面の上の端から見出しの文字まで、絵文字パレットの下の端からバーまで）は上下で同じにし、40pxより広くする（見出しと中身が1つのグループに見えるように）
- 仕組みの図は、2行の見出しの文字の下の端から40px下に置き、下の端をほかの場面の絵文字パレットの下の端にそろえる（図は縮めて収める）。見出しが替わるたびに図が上下に動かないよう、1行の見出しのときも同じ位置にする
- カーソルが選択する位置は、ボタンの実際に描かれた位置から取る。カーソルは選択する前にボタンに着く

## 素材

- 絵文字: fedibird.comのカスタム絵文字のうち、カテゴリがblob*とbunのもので、縦横が1:1のもの（720個）
  - 画像がほぼ透明なもの（動くカスタム絵文字で、最初のコマが透明なもの）は使わない。プロモーションで透明な画像を画像として扱うと、意図を伝えるという目的に反するため
- 入力欄: Sciaに寄せる。入力の行の下に、ボタンの行を並べるだけ
  - 送信ボタンは、入力欄の枠のradiusと同心円になる位置と大きさにする

## 実物と同じにすること

- 絵文字パレットの並びは、実際のSciaと同じにする（`EmojiPalette.swift`）
  - カテゴリの名前の順（`localizedStandardCompare`）に並べ、カテゴリの中はサーバーの応答の順
  - カテゴリごとに見出しを置き、カテゴリが替わったら行を改める
- プリフェッチで流す絵文字の順は、サーバーの応答の順
- 実物と違う並べ替えや混ぜ方をしない

## 用語

- 「くっきりした絵」とは書かない。くっきりしているかは元の画像次第で、Sciaは元の画像をドットバイドット相当に縮めて出しているだけのため。「元の絵」と書く
- 縮めた画像は「サムネイル」と書く

## 場面

### 1. 今までの絵文字パレット

- 指で流すときは、指が触れて動いているあいだ、指が動いた分だけ中身も動く（完全に追従する）。離したときの速さのまま慣性で流れる

| 見出し | 画面 |
|---|---|
| 今までの絵文字パレットは | 絵文字ボタンを選択すると開き、パパッと埋まる。ゆっくり流しても空かない |
| 速く流すと | しゃっと速くはじく |
| ほとんど表示できませんでした（「表示できませんでした」だけを強調） | 空白の枠が出て、遅れて埋まる |

### 2. 新しい絵文字パレット

| 見出し | 画面 |
|---|---|
| 新しい絵文字パレットは | 今までの絵文字パレットは選択して閉じず、開いたまま入力欄と一緒にフェードアウトする。見出しを画面の真ん中に大きく約1秒出し、springで、ほかの見出しと同じ左上の位置と大きさへ動かす。移り終わる頃に入力欄が戻り、新しい絵文字パレットが開く |
| 速く流してもすべて表示できます（「すべて表示できます」だけを強調） | 同じく速くはじいても、空白が出ない |

### 3. 寄る場面

- 1枠に3.4倍で寄り、まわりを暗くする。暗くするのは寄り始めから（ハイライトした枠が入ってくるときからにはしない）。寄ってから流す。ここで流すときは指を出さない
- 寄る動きと引く動きは、見出しの区間とは切り離し、それぞれ約0.6秒のspringにする
- 注目点は、ハイライトした枠の列で、パレットの下の端から半行上の点に固定し、寄る間も引く間も動かさない。その点の画面上の位置が、元の場所から画面の中心へまっすぐ移る（カメラが中心を失わない）
- 寄っている間に流す量は1.5行分（注目点を固定しているので、流しすぎるとハイライトした枠が画面の上へ抜けるため）
- ハイライトした枠は2つ目の見出しの途中で画面の下から入り、4つ目の見出しが始まるときに元の絵に替わり、画面に残る。水色の枠線を付ける
- まわりの絵文字も、サムネイル → 元の絵 に替わる様子が見える
- 見出しは次の4つ（2.2秒、3.5秒、3.5秒、3.0秒）

| 見出し | 画面 |
|---|---|
| なぜ空白が出ないのか | 寄り始め |
| 空白が出るのは読み込みに時間がかかるから | 寄り終えて、ゆっくり流し始める |
| なので最初はすぐ出せるサムネイルを表示して | ハイライトした枠がサムネイルで入ってくる |
| 準備ができたら元の絵に差し替えます | ハイライトした枠が元の絵に替わる |

- メモリの話はしない。本筋ではなく、するならメモリが何で、どう圧迫されるかを見せる場面が要るため

### 3.5 寄る場面のあと

- ズームアウトし終えてから、指ではじいて約1.2秒速く流し、空白が出ないことをもう一度見せる。そのあとフェードアウトする（ズームアウトとフェードアウトを同時にしない）。フェードアウトの間も流し続ける（止める理由がない）
- 仕組みの図の前に「サムネイルはどこから来るのか」を約2.5秒出す。「新しい絵文字パレットは」と同じく、何もない画面の真ん中に大きく出す。ただし続く場面がないので左上へは動かさず、その場でフェードアウトして、仕組みの図に替わる。14文字あり1.44倍では左右の余白（96px）からはみ出すので、余白の中に収まる大きさに抑える

### 4. 仕組み

レイアウト:

- 左に「Mastodonサーバー」。右にスマホ（スマホに保存されることが直感で分かるよう、スマホの形にする。アイランドは描かない。意味がないため）
- スマホの中の上にSciaのカード。アイコンは小さめにして、カードの上の線の真ん中に乗せる。名前は置かない。カードの中は空ける
- スマホの中の下に「ストレージ」。サムネイルの列と元の絵の列を真ん中に置き、左に「ほかのデータ」の枠を置く。列の名前は置かない（見れば分かる）。列の幅は、画像の幅＋余白にする

動き:

- 絵文字は、サーバーの枠から直接出てくる。フェードインせず、枠の中にある部分は描かない
- 線に沿ってSciaのカードに入り、カードの真ん中で受ける。空きが少ないスマホでも真ん中で受ける
- 受けたところで2つに分かれ、真下の列のいちばん上へ入る
- 列の中の絵文字は、上から入ってきた絵文字に押されて下がる。列の下の端を越えた部分は描かない
- 絵文字は止めどなく流れる

| 見出し | 画面 |
|---|---|
| Wi-Fiのときに絵文字をまとめて読み込んで | サーバーからSciaへ絵文字が届き続ける |
| サムネイルを作っておきます | 縮めた形がサムネイルの列へ入り続ける。見出しが出ているあいだ、サムネイルの列の縁が光り、見出しと同じ頃に消える |
| 空きに余裕があれば元の絵も残します | 元の形が元の絵の列へ入り続ける。見出しが出ているあいだ、元の絵の列の縁が光り、見出しと同じ頃に消える |
| 空きが少なければ元の絵は残しません | 別のスマホに替わる。「ほかのデータ」が大きく、元の絵の列がない。縮めた形だけが列へ入り、元の形はSciaのカードの中で消える |
| 表示するときに都度読み込みます | 列のいちばん上の絵文字そのものが持ち上がり（列は詰まる）、Sciaのカードに96pxで表示される。サーバーから元の絵が届いて差し替わり、ストレージへは降りずに消える。3回くり返す |

- スマホが替わるときは、絵文字の転送をいったん止める。Sciaごと入れ替わる（スマホ全体が替わる）
- 空きが少ない場面は、別のスマホにする。もともと使える容量が小さい場合の話なので
- 空きが少ないスマホでは、元の絵の列があった所を「ほかのデータ」で埋める
- スマホの中の角丸は、外側の角と同心円にする。スマホの内側（角60px）から30px内側のSciaのカードとストレージは角30px。ストレージの内側（角28px）から20px内側の「ほかのデータ」と列は角8px。列の中で絵文字を切り取る形も角8px

### 5. 締め

- アプリのアイコンと「Scia」を約3秒
- 最初のコマ（入力欄とバー）へ0.6秒で戻し、ループをつなぐ

## 説明の正確さのための事実

- プリフェッチは自分のサーバーのカスタム絵文字の話。Unicodeの絵文字は端末の中で描くもので、読み込むものではない
- プリフェッチは、元の画像を取得してメモリに置き、そこからサムネイル（32px）を作ってストレージに置く。元の画像は、空きに余裕があるときだけストレージに残す
- サムネイルが速く出せるのは、全部をメモリに読み込んでおける大きさだから（fedibird.comの約6000個で約20MB）。元の絵は合計約140MB（ファイルの大きさ。デコードするとさらに大きい）で、全部をメモリに置くのは現実的でない
- サムネイルは、動く画像の最初のコマから作る（`ImageDecoder.thumbnail`）。最初のコマが透明な絵文字のサムネイルが透明なのは正常
