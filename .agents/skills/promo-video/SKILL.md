# 紹介動画を作る

Sciaの変更を、Mastodonに投稿する短い動画で伝える。コードだけで描き、時刻から決まる絵を1コマずつ撮って動画にする。

このskillの決まりは、2026-11-16に絵文字パレットの紹介動画（`example/`）を作ったとき、ユーザーに指摘されて直したことから作った。見せる前に、ここに書いたことを自分で確かめて直しておく。ユーザーに見せるのは、確かめ終えたものだけにする。

このskillで任せきれないのは、好みと構成の判断（下の「ユーザーに決めてもらうこと」）。そこは案を出して決めてもらい、それ以外は聞かずに決まりどおりに作る。

## 進め方

1. **伝えることを決める。** 何が問題だったか、どう良くなったか、どう解決したか（仕組み）の3つを基本にする。今までの版を過剰に悪く見せない。実際に起きていた場面（例: 開くと一見問題ないが、速く流すと追いつかない）を見せる。仕組みをどこまで説明するか（使う人に分かる理由までか、技術的な理由までか）は、構成案で決めてもらう。
2. **文字で構成案を出す。** 場面ごとに、見出しと画面で起きることを表で書く。いきなり作らない。図の比喩（例: スマホの中にストレージ、サーバーから絵文字が届く）も、この段階で決めてもらう。
3. **specを書く。** 置き場所はscratchpadの作業フォルダー（`spec.md`）。
   - 決まったこと、決まっていないこと、事実（数字と出典）を分けて書く。
   - 決まったことは、過去の版を読まなくても作れるように、最終的な位置、倍率、順序、文言そのものを書く。「v4のまま」「前の版と同じ」「（案）」のような書き方をしない。
   - 決まっていないことには番号を振り、変更前と変更後を表で書く。決まっても消さずに「（決定: …）」と書く。番号を振り直さない（前の番号と別のものを指してしまう）。
   - ユーザーと決めたことは、決めたその場でspecに書く。
   - ユーザーがファイルビューで開いているspecのパスは、毎回送り直さない。
4. **静止画で作り込む。** `scripts/still.mjs`で必要な時刻を撮り、自分の目で見る。値で確かめられることは、`scripts/measure.py`や`page.evaluate`で測る。
5. **決めることは、変更前と変更後で見せる。** 文字の案だけで聞かない。コピーしたHTML（`PAGE=d1.html`）に案を入れて撮り、変更前と変更後を1枚ずつ送る。作業中のHTMLは、決まるまで変えない。
6. **書き出しは、言われたときだけ行う。** 直したあとも、確かめのためにも、勝手に書き出さない。候補が複数あるときは、話の流れで指している1つだけを書き出す。

作業ファイル（HTML、撮った静止画、確認用に並べた画像）と、ユーザーに見せるファイル（`show/`）は、別のフォルダーに置く。見せる画像は並べてくっつけず、1枚ずつ送る。見せる画像は切り取らない（自分で確かめるときは、細部を切り出して拡大して見てよい）。動画はパスで渡す。

## ユーザーに決めてもらうこと

案を画像で出して、選んでもらう。決めたら`spec.md`に書き、次の動画でも同じでよいかを最初に確かめる（今回の決定は`example/emoji-picker-spec.md`）。

- 見出しの文言。agentの案は叩き台で、最終の文言はユーザーが決める。
- 場面の構成と、仕組みの図の形（比喩、何をどこに置くか）。
- テーマ（ライト、ダーク）と配色の方向。迷ったら両方を作って見比べてもらう。
- ロゴの置き方（上か下か、置くだけかバーか、バーの色）。全部の組み合わせを、同じ場面で画像にして見比べてもらう。下に置くなら、中身はロゴの分だけ上へずらす。
- 使う素材（どのサーバーの、どのカテゴリの絵文字か）。
- 強調する範囲、ズームの倍率、ハイライトの長さなど、値を決めたら報告して確かめる。

## 素材

- **色:** シミュレーターで実物のSciaの画面を撮り、そこから画素の色を取る。端末は`sim`のskill（`.agents/skills/sim`）の手順で借り、見たい画面を`scia://`や`scia-debug://`のURLで開いて、`Tools/sim.sh shot '<端末>' --full <ファイル>`で原寸を撮る。ダークとライトは`xcrun simctl ui '<端末>' appearance dark|light`で切り替える。画素は`ffmpeg -i <画像> -vf "crop=1:1:<x>:<y>,format=rgb24" -f rawvideo - | od -An -tx1`で読む。紺の地に水色、上にぼんやりしたにじみ、のような「それらしい」色は使わない（AI生成らしく見える）。
- **アイコン:** SF Symbolsは、ユーザーが書き出したテンプレート（`~/Documents/sfsymbols/symbol/*.svg`）から`scripts/sfsymbol.py`で形を取り出す。自分で描いた形を使わない。足りないシンボルは描かずに、名前を挙げてユーザーに足してもらう（SF Symbolsアプリで、シンボルを選んで「テンプレートを書き出す」で出したSVG）。
- **アプリのアイコン:** Icon Composerの`ictool`で`App/Resources/AppIcon.icon`を書き出す（Liquid Glassのまま）。自分で描いたロゴを使わない。
  ```bash
  "$(ls -d /Applications/Xcode*.app/Contents/Applications/Icon\ Composer.app/Contents/Executables/ictool | head -1)" App/Resources/AppIcon.icon --export-image --output-file <出力>.png --platform iOS --rendition Default --width 512 --height 512 --scale 1
  ```
- **画面の部品:** 入力欄や絵文字パレットは、実物の作り（ボタンの並び、カテゴリの見出しと改行、並び順）に合わせる。実物の決まりはコードで確かめる（例: `EmojiPalette.swift`の並べ方）。実物と違う並べ替えや混ぜ方をしない。
- **カスタム絵文字:** `scripts/emoji_assets.py`で、実サーバーの`api/v1/custom_emojis`から作る（カテゴリで絞る、縦横1:1だけ、実物と同じ並び、透明な画像を除く、大きい画像とサムネイルと`meta.js`を書く）。透明な画像（動く絵文字の最初のコマが透明なもの）のように、画像として意図が伝わらない素材は除く。ただし、それがSciaの不具合でないか（例: 透明な絵文字のサムネイルが透明なのは正常）は、ユーザーに確かめる。

## 配置

値は今回の例。決まりとして守るのは、値ではなく関係。

- 左右の余白は、すべての要素で同じにする（今回96px）。
- 間隔は、見出しの枠ではなく、実際に見える文字や箱の端で測る（`scripts/measure.py`）。
- 見出しと、その下の中身のあいだ（今回40px）は、外側の余白より狭くする。見出しと中身がひとまとまりに見えるため。外側の余白は上下で同じにする。
- バーのように常にある要素を置いたら、その分を除いた領域で、余白と中央を計算し直す。
- 入れ子になった角丸は同心円にする。内側の角の半径＝外側の内側の角の半径−余白。余白は、角を共有する辺で揃える。枠の角に寄せた丸（送信ボタン）も同じ。
- 見出しが1行と2行で替わる場面では、図の位置を2行に合わせて固定し、見出しが替わるたびに図を動かさない。
- 2行の見出しの改行の前に、読点を置かない（「空きが少なければ<改行>元の絵は残しません」）。改行で入力欄やほかの要素と詰まるなら、文言を1行に収まる形にする。
- 何も伝えない飾りやラベルは置かない。要素ごとに、それが何を伝えるかを言えなければ置かない（例: スマホのアイランド、見れば分かる列の名前、右上にあるのと同じアプリの名前）。
- 図の中の大きさで、別の意味を伝えない（例: アプリの枠がストレージを全部埋めているように見える大きさにしない。列の幅は画像の幅＋余白）。

## 動き

- **springで動かす。** 位置や大きさが変わる動き（見出しの移動、列を空ける動き、寄る動き）は、閉じた形のspring（`1 − e^(−wτ)(1 + wτ)`）で動かす。
- **指で流すときは、指に完全に追従させる。** 指が触れて動いているあいだは、指が動いた分だけ中身も動き、離したときの速さのまま慣性で流れる。指の位置と中身の位置を、同じ関数から出す。
- **カーソルは、選択する前にボタンに着く。** 選択する位置は、ボタンの実際に描かれた位置（`getBoundingClientRect`）から取る。座標を決め打ちしない。
- **今までの版と新しい版の切り替わりを、見て分かるようにする。** 同じ画面が続くと、同じものが開き直したようにしか見えない。区切りの見出しを、何もない画面の真ん中に大きく出す。消えるものは、閉じる操作を見せずにフェードアウトさせる（フェードアウトするなら、選択して閉じる操作は要らない）。
- **寄る動き（ズーム）:**
  - 寄ってから流す。寄った場面では、注目した1つだけでなく、まわりの要素も同じ処理（例: サムネイル→元の絵）に従う様子を見せる。
  - 注目点を固定し、その点の画面上の位置が、元の場所から目標へまっすぐ移るように書く。`translate(lerp(f, 目標, p) − f·s) scale(s)`。`translate((中心 − f·s)·p)`のような式は、注目点が弧を描いて中心を失うので使わない。
  - 寄る動きと引く動きは、見出しの区間とは切り離して、それぞれ約0.6秒のspringにする。
  - 注目点の要素が、寄っている間ずっと画面の中にあることを値で確かめる。
  - 寄っている途中で指を見せない（カメラが動くので、指と中身の動きが揃わない）。
- **場面の切り替えで中身を止めない。** フェードアウトの間も流し続ける。
- **ズームとフェードを同時にしない。** 引き終えてからフェードする。
- **流れの向きを揃える。** 上から入ってくるなら、列は上に積み、古いものを下へ押し下げる。
- **続く流れは止めどなく流す。** 例外は、受け手そのもの（例: スマホ）が入れ替わるあいだで、そこでは転送を止める。数珠つなぎに重なるなら、間隔ではなく、通り道の長さと時間で直す。
- **押し下げでgapや重なりを作らない。** 列に積む動きは、1つの要素のまま入り、上から入ってきたものに押されて下がる形にする（途中で別の要素に描き替えない）。
- **着地と受け渡しの位置を値で確かめる。** 通り道の終わりが、受け手の枠の中（例: 列のいちばん上、囲みの真ん中）に来ているかを、受け手が替わる場面ごとに確かめる。
- **切り取りは、枠と同じ形で行う。** 角丸の枠なら角丸で切り取る。枠に入る前の位置では切り取らない。
- **飛んでくるものは、枠の中から直接出す。** フェードインさせず、枠の中にある部分は描かない。
- **文字やアイコンの上を通らない通り道にする。** 通ってしまうなら、置き場所を動かすより、受ける側の作りを見直す（例: アイコンを囲みの上の線に乗せ、囲みの中を空ける）。

## 見出し

- 読み切れる時間を出し、前後の見出しと文の量の釣り合いを取る。短い問いのほうが長い説明より長く出る、という逆転を作らない（寄る場面では1文字0.12秒＋1秒にした）。
- 対になる見出しは、言葉をそろえる（「ほとんど表示できませんでした」と「速く流してもすべて表示できます」）。強調は、対になる部分だけにする。
- 話が唐突に変わらないようにする。場面が替わるたびに、前の場面とのつながりを確かめる。結果から仕組みの説明へ移るときは、問いの見出しで区切る（「なぜ空白が出ないのか」「サムネイルはどこから来るのか」）。
- 区切りの見出しの出し方:
  - 実演の上に重ねる見出し（「なぜ空白が出ないのか」）は、ほかと同じ左上に出す。
  - 独立した区切りの画面（「新しい絵文字パレットは」「サムネイルはどこから来るのか」）は、何もない画面の真ん中に大きく出す。次の場面でも同じ見出しを使うなら、springで左上の見出しの位置へ動かす。使わないなら、その場で消す。左右の余白からはみ出すなら、大きさを抑える。
- 図のハイライト（例: 列の縁を光らせる）は、それを説明している見出しが出ているあいだ続け、見出しと同じ頃に消す。
- AIらしい文言にしない。
  - 宣伝の決まり文句のような短い言い切り（「全部見えます」）、体言止めの煽り、読点で溜める言い回し（「でも、しゃっと速く流すと、」）、本文を縮めただけのタイトルにしない。
  - ユーザーが直した例: 「一見、問題ない。」→「今までの絵文字パレットは」、「でも、しゃっと速く流すと、」→「速く流すと」。
  - 言い回しは`AGENTS.md`の文言の決まりに従う。
- 数字や程度を表す言葉は、測ったデータに合わせる（例: 空白が55〜94%なら「ほとんど表示できませんでした」と言ってよい）。「過剰に悪く見せない」は、データより悪く言わないという意味で、データどおりに言うことを避ける理由にしない。

## 説明の正確さ

- 仕組みの説明は、コードで確かめた事実だけにする（例: サムネイルは動く画像の最初のコマから作る、プリフェッチはWi-Fiのように通信量に限りがない回線でだけ動く）。確かめた行をspecの「事実」に書く。
- 画面に描く図は、実際の処理の順番と一致させる（例: 元の画像はまずメモリに入り、そこからサムネイルを作ってストレージに置く）。
- 図のラベルと見出しの語は、ぼかさず実物の名前にする（「インターネット」ではなく「Mastodonサーバー」、「この端末」ではなく「ストレージ」、「小さい絵」ではなく「サムネイル」）。品質を保証する語（「くっきりした絵」）は使わない。くっきりしているかは元の画像次第なので、「元の絵」と書く。
- 説明に要らない概念は入れない（例: メモリの話は、何がどう圧迫されるかを見せる場面が要るので入れなかった）。
- 数字を出すなら、解釈に要る前提（どのサーバーの、何件で、何の大きさか）も一緒に出す。前提なしの数字（「20MB」）は、多すぎるように見える。

## 道具

`scripts/`に置いてある。

**前提:** Node.js、Python 3、ffmpeg、Google Chrome（`channel: 'chrome'`で使う）、`playwright-cli`に同梱された`playwright-core`（場所は`PLAYWRIGHT_CORE`で変えられる）。作業フォルダーは絶対パスで渡す（`file://`につなぐため）。

- **HTMLの作り:**
  - `window.ready`（画像を読み込み終えるPromise）と、`window.render(t)`（時刻`t`秒だけから絵を決める関数）を置く。前のコマの状態に頼らない。DOMの位置を読む処理（カーソルが選択する位置など）は、その時刻の変形を当て終えてから読む。
  - 同じ時刻を、前から順に描いたときと、別の時刻から飛んで描いたときで、同じ絵になることを確かめる。
  - 実例は`example/emoji-picker.html`。素材（`appicon.png`、`fe4/big/*.png`、`fe4/small/*.png`、`meta.js`）は含めていない。`scripts/emoji_assets.py`と`ictool`で作る。完成形のロゴの置き方で見るには、`Q='?theme=light&logo=bottom&style=bardark'`を付ける。
- **静止画:**
  ```bash
  Q='?theme=light' PAGE=index.html node scripts/still.mjs <作業フォルダー> 3 12.5 33.5
  ```
  `s_<時刻>.png`を書く。ページのエラーや、画像の読み込みの失敗があれば、終了コード1で止まる。撮る前に画像のデコードを待つ（待たないと、読み込んだはずの画像が写らない）。
- **書き出し（言われたときだけ）:**
  ```bash
  rm -rf <コマのフォルダー> && mkdir <コマのフォルダー>
  Q='?theme=light' nice -n 10 node scripts/render.mjs <作業フォルダー> <秒> <コマのフォルダー> 3
  nice -n 10 ffmpeg -framerate 240 -i <コマのフォルダー>/%05d.png -t <秒> -vf "tmix=frames=4:weights='1 1 1 1',fps=60" -c:v libx264 -crf 17 -pix_fmt yuv420p -an <出力>.mp4
  ```
  - 60fps×4サブフレームを撮り、`tmix`でモーションブラーをかける。
  - コマのフォルダーは毎回空にする。
  - 並列は3まで、`nice`で優先度を下げる（8並列で、10コアのMacのロードアベレージが260になった）。走っている間に`sysctl -n vm.loadavg`を見て、コア数（`sysctl -n hw.ncpu`）を大きく超えるなら止めて並列を減らす。
  - 書き出したら、`ffprobe`で長さ、大きさ、fps、音声がないことを確かめ、最後のコマから最初のコマへつながることを見る。
- **確かめ:**
  - `python3 scripts/measure.py <画像>`で、地と違う色の行のかたまり（文字、色の付いた帯）と、地より明るい箱の上下の端を出す。地の色は引数で変えられる。
  - 動きは、書き出した動画から続きのコマを並べて見る（`ffmpeg -ss <秒> -i <動画> -vf "select='lt(n,12)',tile=4x3" -frames:v 1 <出力>.png`）。1秒ごとのコマだけで「動きが正しい」と言わない。
  - 気になる見え方は、まず値（`getBoundingClientRect`、`clipPath`、`opacity`、素材の不透明度）で原因を確かめてから直す。見た目から原因を推測して報告しない（今回、透明な絵文字がgapに見えたのを、springのせいだと3回誤って報告した）。
  - ユーザーに「該当部分を見ろ」と言われたら、その時刻のコマを原寸で取り出し、その部分を拡大して自分の目で見てから答える。
- **SF Symbols:** `python3 scripts/sfsymbol.py <名前> <大きさ>`で、テンプレートのRegular-Sの形を、文字の高さの基準でそろえたSVGにして出す（シンボルどうしの大きさの違いを残す）。

## ユーザーとのやりとり

- 構成案にない場面、見出し、演出は、案を出して合意を取ってから入れる。合意を取らずに作業中のHTMLに入れない。
- 自分で決めたこと（式、時間、並べ替え、余白の値など）は、聞かれる前に報告に書く。指示されていないレイアウトやズームの倍率を変えない。
- 質問の意図が分からないときは、推測で作らずに、読み取った意味を書いて確かめる（「同じスタイル」の意味を取り違えて、違う案を作った）。
- 報告の「確かめた」は、確かめた方法（どの時刻の静止画か、何を測ったか）と一緒に書く。確かめていないことを確かめたと書かない。
