# リンクカード

投稿の本文のリンクに付けるカードをどう出すかで、作者が決めたこと。

## 形

- カードは常に、片側にサムネイル、もう片側に文字を並べた、決まった高さの小さい形で出す。サムネイルを横幅いっぱいに出す大きい形は使わない
- サムネイルを左右どちらに置くかは、設定で選ぶ。既定は左。画面の向きによらず、左右をそのまま指す
- 文字は、サムネイルの位置によらず、その文字の言語の書く方向に寄せる。右から書く言語の見出しは右に寄せる
- 画像のあるカードは、画像を押すと、投稿の添付ファイルと同じビューアで画像を開く。画像のほかの場所を押すと、リンクを開く
- サムネイルの有無や、カードが後から届いたかどうかで、行の高さを変えない。カードが後から届いても、タイムラインをガタつかせないため
- 画像のないカードには、サムネイルの枠を出さず、文字を左端から並べる。まだカードが届いていない、リンク先だけのカードには、リンクの記号を入れた枠を出す
- リンク先だけのカードに、画像のないカードが届いたら、枠を縮めて消し、文字を左へ寄せる動きでつなぐ

## 閲覧注意

- 閲覧注意か注意書きのある投稿では、カードの画像を、添付ファイルと同じく閲覧注意としてぼかす。ぼかしている間は画像を読まず、blurhashのぼかしの上に、目の記号だけを重ねる。サムネイルは小さく文字が入りきらないため、添付ファイルを1列に並べるときと同じく、文言は出さない
- ぼかした画像を押すと、ぼかしを外す。リンクは開かず、ビューアでも開かない。ぼかしを外したあとは、ぼかしていないカードと同じく、画像を押すとビューアで開く。文字の部分を押すと、ぼかしている間もリンクを開く
- ぼかしを外したことは、添付ファイルと同じく投稿ごとに覚え、同じ投稿のブーストや通知の行、ほかのタブにもそろえる。添付ファイルとカードの画像が同じ投稿に並ぶのは、カードの付いた投稿に、本文を変えずに添付ファイルを足して編集したときだけで、そのときはどちらのぼかしを外しても両方外れる
- 外したぼかしを、メニューから掛け直すことはできない。添付ファイルの「メディアを隠す」は、カードの画像には効かない
- 画像のないカードと、リンク先だけのカードには、ぼかす画像がないため何も重ねない

## カードが後から届くこと

Mastodonは、投稿を配信してからリンク先を取りに行き、カードを付ける。自分のサーバーの投稿では数秒、ほかのサーバーの投稿では、取りに行くのを最大1分遅らせるため、それ以上かかる。カードが付いても、ストリーミングで更新は流れない。そのため、ストリーミングや投稿の直後の応答で受け取った投稿の多くは、カードがない。Webで、自分の投稿のカードが、お気に入りなどで投稿を取り直すまで出ないのもこのためである。

- カードが付きそうな投稿には、受信した時点でカードの枠を出し、通信せずに分かるリンク先のドメインとURLを入れておく。付きそうな投稿は、サーバーと同じく、本文の最初のリンク（メンションとハッシュタグを除く）があり、メディアも引用もない投稿とする
- カードがない投稿は、間を空けてサーバーから取り直し、届いたカードで枠を埋める
- サーバーがカードを作らなかったときも、枠を消さず、ドメインとURLの表示を残す

## 端末でカードを作る

- サーバーが作らなかったカードを、端末がリンク先を取りに行って作る機能は、オプトインにする
- オンにする画面で、投稿を表示しただけで端末がリンク先にアクセスすること、見たことがリンク先に分かること、通信量が増えることを示す
- 端末で作ったカードを出したあとに、サーバーのカードが届いたら、サーバーのカードに差し替える

## Xの投稿

サーバーのカードは、Xの投稿には画像を1枚しか付けず、動画のURLも2枚目以降の画像もない。年齢制限のある投稿では、本文の代わりに英語の定型文が入る。そのため、Xの投稿へのリンクは、端末がXの投稿を読み、リンクカードの代わりに、作者、本文、添付ファイルの囲みで出す。

- Xの投稿は、fxtwitterのAPIだけから読む。Xのsyndicationは、年齢制限のある投稿の中身を返さないため使わない。ほかの読む先に切り替えることもしない
- 囲みは、Mastodonの引用と同じ部品で作る（[quote.md](quote.md)）
