# お気に入りとブーストの光

自分がお気に入りやブーストをした投稿を、どう見せるかで、作者が決めたこと。Sciaには投稿ごとのアクションバーがないので、アクションバーのボタンの色で状態を見せることはしない。

## 形

- お気に入りやブーストをした投稿は、行の下の端から上へ照らす光で示す。光は行の中身の後ろに重ねて描き、行の高さや本文の幅を変えない。光は行の中にだけ伸ばし、行より高ければ上の端で切る
- 両方したときは、左半分をブースト、右半分をお気に入りの色にし、真ん中で混ぜる。片方だけのときは、その色で全幅を光らせる。半分だけ光った帯は、半分まで進んだ進み具合のバーのように見えるため
- ブーストは緑、お気に入りは、ダークでは黄色、ライトでは橙にする。白い背景では黄色が見えにくいため
- 2色は1本のグラデーションで描き、真ん中で暗くならないようにする。2色を別々に薄くして重ねると、真ん中で覆う割合が足りずに暗くなるため。混ぜる色は、sRGBの値のままではくすむため、光の強さ（線形）で計算する
- 光は下の端がいちばん明るく、上へ離れるほど薄くなる。下の端には、光源として細く明るい線を置く
- 光っている行では、一覧の区切り線を消し、光の下の端を区切りにする。区切り線が光に重なると、光源が灰色に濁って見えるため
- 光の色だけでは何を示すか分かりにくいので、下の端に、ブーストの⟲とお気に入りの★を、それぞれの光の位置に薄く添える。両方なら、それぞれの半分の真ん中に置く。アイコンは本文の下の余白に収め、本文に重ねない
- 読み上げでは、行のラベルに「ブースト済み」「お気に入り済み」を足す
- 投稿の行のほか、自分の投稿の再掲になる通知の行と、設定画面の見本の投稿にも出す

## HDR

- HDRで描ける画面では、光を白より明るいHDRの色で描く。白い背景より明るい色はSDRでは描けず、ライトでは光が色の付いた帯にしか見えないため
- ライトでは、照らされた面を「背景の白に光を足した色」で描く。光の色を明るくして白に重ねるだけでは、光の色にない成分（橙なら青）が白より暗くなり、面が明るくならずに色が付いて見えるだけになるため
- ダークでは、照らされた面はSDRで描き、下の端の光源だけをHDRで描く。黒い背景の上では、SDRの色でも光って見えるため
- HDRで描けない画面（白より明るくできる余地が1倍、iPhone SEなど）では、SDRで描く。白より明るい色は白に丸められ、ライトでは光が見えなくなるため
- HDRで描くかは、設定の「HDRで光らせる」で選ぶ。既定はオン。HDRのメディアの明るさの設定はメディアに対するものなので、光はそれに従わせない。設定の項目の上に、お気に入りとブーストをした見本の投稿を出し、切り替えたときの見え方をその場で見られるようにする
- 画面がその場で白の何倍まで明るく描けるか（今の余地）を見て、SDRへ切り替えることはしない。iOSは光のような内容に白の1.2倍ほどしか割り当てず、光を明るくしても、周りが明るくなっても、この値は変わらなかったため
- ライトでSDRで描くときは、光を低くする。白い背景に光の色を薄く重ねるだけなので、高くすると汚れのように見えるため

## 動き

- お気に入りやブーストをしたとき、取り消したときは、光を点けたり消したりする動きでつなぐ。同じ投稿のまま状態が変わったときだけ動かし、行が別の投稿に使い回されたときは、すぐに切り替える
- 点けている途中に取り消されても、今の明るさから戻す。押したときの強調などで同じ状態がもう一度描き直されても、進んでいる動きを止めない
- 両方のうち片方を足したとき、全幅に光っていた色は、もう片方が点くのに合わせて自分の半分へ寄る。アイコンも、真ん中からそれぞれの半分の真ん中へ動く。視差効果を減らす設定では、アイコンを動かさずに行き先へ置き、濃さだけを変える
