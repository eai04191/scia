# 画像の読み込み

カスタム絵文字、アイコン、添付ファイル（リンクのカードやプロフィールのヘッダーの画像を含む）を、サーバーから取得するときに、作者が決めたこと。

## 応答の扱い

- 2xx以外の応答の本文は、画像として扱わない。サーバーの障害のページ（503や404のHTML）を画像としてデコードすると、読めない画像と区別できなくなるため
- 失敗の分け方、再開の時刻でホストごとに止めること、その場での送り直し、大きさの上限は、ほかの通信と同じ決まりに従う（[通信](network.md)）

## 読めなかった画像の読み直し

- 待てば直る失敗（通信の失敗、408、429、5xx）は、行を描いたときに、間隔をおいて読み直す。Xの投稿と動画の最初のコマも、同じ間隔で読み直す。間隔は5秒から始め、続けて失敗するたびに倍にして、60秒で止める。値はチューニングで変えられる
  - 一度読めなかっただけで、起動し直すまで読まないことはしない。トンネルやバックグラウンドから復帰した直後の一時的な失敗で、絵文字が`:shortcode:`の文字のまま戻らなくなるため
  - 描くたびにすぐ読み直すこともしない。相手のサーバーが落ちていると、スクロールのたびに同じ画像を読みに行くため
- 応答が再開の時刻を示していれば、間隔より遅いときはそれまで待つ
- Mastodonは`/media_proxy`への読み込みをIPごとにまとめて制限する。429が来たら、同じサーバーの`/media_proxy`の画像を、まだ読んでいないものも含めて、再開の時刻まで読まない。止めないと、ほかの画像がそれぞれ429を受けに行く。サーバーが保存し直した画像は制限が掛からないので止めない
  - 止めるのは、429を受けたストア（絵文字、アイコン、添付ファイルのそれぞれ）の自動の読み込みだけで、ストアをまたいでは止めない
- 待っても直らない失敗（そのほかの4xx、画像として読めないデータ）は、自動では読み直さない。アカウントや投稿が読み直されれば、新しいURLで読む
- 使う人が自分で見に行った操作（ビューアを開く、長押しして持ち上げる、投稿のメニューを開く）では、間隔を待たずに読み直す。せっかちに押したのに何も起きない、という形にしないため
- 読み直している間も、読めるまでは前と同じ表示（絵文字なら`:shortcode:`の文字）のまま描く。読み直すたびに表示が空白と行き来しないため
- 先読みと、新着を入れる前のアイコンの待ちでは、前に読めなかった画像を読まない。読めない画像のために通信を増やしたり、挿入を遅らせたりしないため

## ビューアで開く画像の先読み

ビューアで開くと、元の画像を読み終えるまでサムネイルを引き伸ばして待たせることになる。Wi-Fiでは、開きそうな画像を先に読んでおき、開いたときに通信せずに出す。

- 先読みは通信の目的の「先読み」で送る（[通信](network.md)の「通信の目的」）。Wi-Fiのように通信量に限りがなく低データモードでもない回線でだけ送り、レート制限で止められている間も送らない
- 読むのは、一覧のスクロールが止まったときに画面に出ている投稿と通知の、画像の添付ファイルだけ。引用元の画像も含める。ぼかしている画像も、外したらすぐ開けるよう読む（[タイムラインのメディア](timeline-media.md)の「状態の表示」）。スクロールが始まったら止め、流し見で通り過ぎた投稿は読まない。Mastodonの`/media_proxy`はIPごとに制限するため、まとめて読むと429を受け、一覧のサムネイルまで止まってしまう
- 動画、GIF、音声は読まない。再生はAVFoundationが開いてから少しずつ読むので、先に全部落とすと大きく、待ちも縮まらない
- 1つずつ読む。スクロールして画面から外れた画像の読み込みは止め、新しく画面に出た画像を上から順に読む
- ビューアと同じURL（元の画像、なければ他のサーバーの元の画像）を読み、展開せずにファイルのまま置く。展開すると1枚で数十MBのメモリを使うため、展開はビューアで開いたときに行う
- 一覧のサムネイルに元の画像を読んだとき（[通信](network.md)の「質を上げる」）も、同じファイルを先読みの置き場に置く。サムネイルとして読んでいる途中なら、先読みはそれを待つ。同じファイルを2回読まないため
- 同じ画像を、回線の制限の違う目的（ぼかしている間の先読みと、外したあとの表示など）で読んでいる途中なら、その結果を待つ。OSが回線を理由に断ったときだけ、待った側が自分の目的で読み直す
- 置き場は、ビューアで開いた画像のキャッシュ（メディアのキャッシュ）とは分け、合計100MBまでにする。超えたら、置いた日時の古いものから消す。開いていない画像で、開いた画像を押し出さないため
- ビューアで開いたら、先読みしたファイルをメディアのキャッシュへ移す。ログアウトしたら、先読みを止め、メディアのキャッシュと一緒に消す
- 設定のストレージでは、「メディアのキャッシュ」の合計の下に「表示済み」と「先読み」の2段を並べ、それぞれの大きさを出す。どちらの段も、押すと中身の一覧を開き、Quick Lookで見て共有や保存ができる。消すボタンも段ごとに置く。置き場を分けたものを1つの項目に数えるときは段を分け、大きさに数えているのに中身を見られない、という食い違いを作らないため
- 読めなかった画像は、読み直しの間隔に従う（上の「読めなかった画像の読み直し」）。前に読めなかった画像は先読みしない
- 先読みの途中にビューアで同じ画像を開くと、ビューアは先読みを待たずに自分で読む。同じ画像を2回読むことになるが、Wi-Fiでだけ起き、待ち合わせのために先読みの置き場とビューアの読み込みを結ぶ手間に見合わないため

## 縮めて展開する

- 画像は、描く大きさまで縮めて、メインスレッドの外で展開する。元の大きさのまま展開すると、大きな写真では時間がかかり、メモリも食うため
- 文字の中に描く絵文字は、高さで縮める大きさを決める（[動くカスタム絵文字](animated-custom-emoji.md)の「コマの読み方」）
