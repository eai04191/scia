# 画像の読み込み

カスタム絵文字、アイコン、添付ファイル（リンクのカードやプロフィールのヘッダーの画像を含む）を、サーバーから取得するときに、作者が決めたこと。

## 応答の扱い

- 2xx以外の応答の本文は、画像として扱わない。サーバーの障害のページ（503や404のHTML）を画像としてデコードすると、読めない画像と区別できなくなるため
- 失敗の分け方、再開の時刻でホストごとに止めること、その場での送り直し、大きさの上限は、ほかの通信と同じ決まりに従う（[通信](network.md)）

## 読めなかった画像の読み直し

- 待てば直る失敗（通信の失敗、408、429、5xx）は、行を描いたときに、間隔をおいて読み直す。Xの投稿と動画の最初のコマも、同じ間隔で読み直す。間隔は5秒から始め、続けて失敗するたびに倍にして、60秒で止める。値はチューニングで変えられる
  - 一度読めなかっただけで、起動し直すまで読まないことはしない。トンネルやバックグラウンドから復帰した直後の一時的な失敗で、絵文字が`:shortcode:`の文字のまま戻らなくなるため
  - 描くたびにすぐ読み直すこともしない。相手のサーバーが落ちていると、スクロールのたびに同じ画像を読みに行くため
- 応答が再開の時刻を示していれば、間隔より遅いときはそれまで待つ
- Mastodonは`/media_proxy`への読み込みをIPごとにまとめて制限する。429が来たら、同じサーバーの`/media_proxy`の画像を、まだ読んでいないものも含めて、再開の時刻まで読まない。止めないと、ほかの画像がそれぞれ429を受けに行く。サーバーが保存し直した画像は制限が掛からないので止めない
  - 止めるのは、429を受けたストア（絵文字、アイコン、添付ファイルのそれぞれ）の自動の読み込みだけで、ストアをまたいでは止めない
- 待っても直らない失敗（そのほかの4xx、画像として読めないデータ）は、自動では読み直さない。アカウントや投稿が読み直されれば、新しいURLで読む
- 使う人が自分で見に行った操作（ビューアを開く、長押しして持ち上げる、投稿のメニューを開く）では、間隔を待たずに読み直す。せっかちに押したのに何も起きない、という形にしないため
- 読み直している間も、読めるまでは前と同じ表示（絵文字なら`:shortcode:`の文字）のまま描く。読み直すたびに表示が空白と行き来しないため
- 先読みと、新着を入れる前のアイコンの待ちでは、前に読めなかった画像を読まない。読めない画像のために通信を増やしたり、挿入を遅らせたりしないため

## 縮めて展開する

- 画像は、描く大きさまで縮めて、メインスレッドの外で展開する。元の大きさのまま展開すると、大きな写真では時間がかかり、メモリも食うため
- 文字の中に描く絵文字は、高さで縮める大きさを決める（[動くカスタム絵文字](animated-custom-emoji.md)の「コマの読み方」）
