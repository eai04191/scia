# ステータスバーの通知

届いた通知（お気に入り、ブースト、返信、フォローなど）を、ステータスバーの場所に1件ずつ流す。通知タブを開かなくても、反応が来たことに気づけるようにするため。作者が決めたこと。

## 出すもの

- 左に、何をされたかの記号、操作した人のアイコン、名前を出す
- 右に、対象の投稿の文頭を出す。文字のない画像だけの投稿なら、最初の添付ファイルのサムネイルを出す。フォローなど対象の投稿がない通知では、操作した人のアカウント名を出す
- 返信の先頭に並ぶ宛先のメンションは省く
- 注意書き（CW）のある投稿は、本文ではなく注意書きを出す。閲覧注意の画像は、サムネイルを覆う
- 通知の一覧と同じくサーバーのフィルターを当てる。警告に一致した投稿は本文を見せずに「フィルター「名前」に一致」と出し、ぼかしに一致した画像はサムネイルを覆う。隠すに一致した通知は流さない
- 入りきらない名前と文頭は、「…」で切らず、行末をぼかす

## 形

- アイランドの機種では、アイランドと同じ丸みの黒いカプセルを、アイランドから左右に広げて浮かせる。カプセルの形は変えない
- カプセルは、画面の外形をアイランドの上の余白（アイランドの上から画面の上端まで）だけ内側へ縮めた範囲に、カプセルの縦の真ん中の左右の端が収まるところまで広げる
- 中身の左の余白は、記号ごとに変えず1つの値にする。丸に近い記号が、カプセルの端の半円と同心に見える値にする
- 中身の右の余白は、行末のぼかしの区間がカプセルの端の半円に入る値にし、ぼかしとは別に余白を足さない
- 左右の余白と、行末をぼかす幅は、チューニングで変えられる
- ノッチの機種では、ノッチから左右に広げる。左が狭いので、何をされたかの記号はアイコンに重ねる
- 切り欠きのない機種（iPhone SE、iPad）では、黒い帯を張らず、ステータスバーの文字を入れ替えたように、地を透かしてふだんの文字の色で描く
- Macでは、ステータスバーは描かれないが、ナビゲーションバーの上にステータスバーの高さの帯が空いているので、そこにiPadと同じ形で描く。通知を開かずに気づける場所が、ほかにないため
- 出している間だけ、ステータスバーを隠す
- アイランドとノッチの位置と大きさは、機種ごとに測った値を機種の識別子で引く。拡大表示では、画面の幅の比で縮める
- 値を測っていない機種では流さない。切り欠きの形を推し量ると、切り欠きとずれた黒を描くため

## 動き

- アイランドから左右へ広げて出し、アイランドへ縮めてしまう。中身は背景の左右の端から決まった余白で付いて動き、広がり終わる位置で止まる
- スプリングは、UIKitの`usingSpringWithDamping`と同じ曲線にする。iOSらしく見えるため
- 次の通知へは、背景はそのままで、中身を上へ送って入れ替える

## 流し方

- 通知はまとめずに1件ずつ流す。たくさん来ているように見えるほうが面白いため
- 待っている通知が多いほど、1件を出しておく時間を縮めて続けざまに流す
- 押すと通知タブを開く。投稿を1件だけ開く画面ができたら、そちらにする
- 通知タブを見ている間、ビューアのように画面全体を覆う画面を出している間、iPhoneの横向き、ウィンドウ表示のiPad（ステータスバーがウィンドウの上になく、流すと操作ボタンに重なる）、バックグラウンドでは流さない
- 設定でオン・オフを切り替えられる。既定はオン
- 値を測っていない機種では、設定の切り替えをオフにして灰色にし、この機種では使えないことと理由を添える。黙って流さないと、使う人には不具合に見えるため

## やめたこと

- 画面の上端につなげる形（下の端を画面の縁へ流し込む形、下の角を丸める形、角を丸めず縁まで伸ばす形）。黒い板を貼ったように見えるか、画面の角と調和しなかった
- ナビゲーションバーの奥まで黒くする形
- カプセルを画面の外まで広げる形。減速するところが画面の外で過ぎ、画面の中ではリニアに動いて見えた
- カプセルの上半分だけを画面の角と同心の丸みにする形。カプセルの高さでは丸みが入らず、無理に描くと上下の丸みの境で折れ目ができる
- 自前のスプリングの曲線で動かす形。出だしが遅くほぼ一定の速さで進み、iOSらしく見えなかった
