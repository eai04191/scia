# サーバーのフィルター

サーバーのフィルターの扱いで、作者が決めたこと。

- 自分の投稿には、フィルターを当てない。公式のWebクライアントと同じ。サーバーは自分の投稿にも一致したフィルターを付けるが、当てると、投稿した直後の自分の投稿が隠れて、投稿に失敗したように見えるため
- 代わりに、自分の投稿がフィルターに一致したら、折りたたまずに「フィルター「A」に一致」の1行を出す。昔作ったフィルターに一致する話題を自分が書くと、それに触れた人の投稿が黙って隠れ、フィルターがあることに気づけないため
- ブックマークとお気に入りのタイムラインでは、「隠す」に一致した投稿も隠さず、警告で折りたたむ。公式のWebクライアントと同じ。自分で残した投稿を、タイムラインから黙って消さないため
- フィルターが変わったこと（ストリーミングの`filters_changed`）が届いても、表示している投稿には反映しない。読み込み直したときに反映される。表示している投稿に反映するには、タイムラインを読み込み直すか、キーワードを手元で照らし合わせる必要があり、作業が大きいため

## 作る、変える、消す

- 入口は、アカウントの画面の「フィルター」と`scia://filters`。サーバーのアカウントに属するものなので、設定には置かない（[account-screen.md](account-screen.md)）
- 扱うのはキーワードのフィルターだけ。投稿を1件ずつフィルターに足すことと、足した投稿の一覧や解除は、まだ作らない。webなどで足した投稿は、フィルターを変えても残し、編集の画面に件数だけを出す
- フィルターの画面は、自分のフィルターを名前の順に並べる。APIは順を決めずに返し、Mastodonのwebの設定は名前の順に並べているため。右上の＋で作り、項目を押して変え、左へスワイプするか編集の画面の「フィルターを削除」で、確かめてから消す。期限の切れたフィルターは「期限切れ」と出す
- 編集の画面は、名前、期限、対象、一致した投稿の扱い、キーワードを1画面に並べ、「保存」で1回のリクエストにまとめて送る。キーワードごとにリクエストを分けると、途中で失敗したときに半分だけ変わるため
- 期限は、ハッシュタグのミュートと同じ長さの選択肢から選ぶ。期限は保存したときから数えるので、変えるフィルターでは、今の期限をそのままにする選択肢を先頭に置いて選んでおく
- フィルターの数と、名前やキーワードの長さの上限はAPIで返らないので、手元では止めない。サーバーが断って返した理由を、保存できなかったときのアラートに出し、閉じると入れた内容を残したまま編集に戻す
- 「ぼかす」はMastodon 4.4からの扱いだが、サーバーのバージョンでは出し分けない。古いサーバーが断ったら、理由をアラートに出す
- 保存や削除をしても、表示している投稿には反映しない。`filters_changed`と同じく、読み込み直したときに反映される。ハッシュタグのメニューの「ミュート」が見る、覚えているフィルターは読み直す
- ハッシュタグのミュートで作ったフィルター（[menus.md](menus.md)）は、ほかのフィルターと区別せずに並べ、同じように変えられる。`#名前`のキーワードを消したり、扱いを「隠す」のほかに変えたりすると、ミュート中ではなくなる
