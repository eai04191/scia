# 検索

ユーザー、ハッシュタグ、投稿を探す画面で、作者が決めたこと。探すのはMastodonの`GET /api/v2/search`で行う。

全文検索（Elasticsearch）を入れていないサーバーでは、投稿は探せない。そうしたサーバーでの検索は、URLだけ分かっている投稿を読み込むことと、プロフィールを開くことに使う。サーバーが全文検索に対応しているかは、APIからは分からない。対応していないサーバーも、検索に失敗したサーバーも、投稿を空の配列で返すため。

## 置き場所

- タブの並びに置ける項目にする。既定で有効にし、通知の後ろに置く。既定の並びは、ホーム、ローカル、連合、通知、検索の5つになり、切り替えタブを使わずに収まる
- システムの検索タブ（`UISearchTab`）は使わない。iOS 27では、切り替えタブを目立たせるタブにしてタブバーの右端に切り離して置いており、検索タブも同じ右端に置かれるため
- 検索欄は画面の上（`navigationItem.searchController`）に置く。画面の下には投稿欄のカプセルがあるため
- タブを開いたときに検索欄が空なら、検索欄にフォーカスを入れ、すぐ打てるようにする
- 結果から開いたスレッド、プロフィール、ハッシュタグは、ほかのタブと同じく、このタブの中に積んで開く
- `scia://search?q=<パーセントエンコードした語>`で、検索のタブに語を入れて確定した状態で開く。`q`を付けなければ、検索のタブを開くだけにする。検索を無効にしていれば、今見ているタブに検索の画面を積んで開く

## 打っている途中

- 打つたびに、ユーザーとハッシュタグの候補を出す。投稿欄の補完と同じく、自分のサーバーが知っているものだけを探し（`resolve=false`）、前の問い合わせは取り消し、失敗しても送り直さない。打つたびに相手のサーバーへ問い合わせると遅いため
- 候補の上に、打った語に応じて次の行を出す。押すと、それぞれ確定と同じことをする
  - 「“語”を検索」: いつも出す
  - 「このURLを開く」: httpかhttpsのURLのとき。候補は探さない
  - 「@user@domainを開く」: ハンドルの形のとき
  - 「#名前を開く」: `#`で始まるとき。ハッシュタグの一覧を開く
- 候補のユーザーを押すとプロフィール、ハッシュタグを押すとハッシュタグの一覧を開く
- 検索欄が空のときは、最近の検索を出す

## 確定したとき

キーボードのReturnか、「“語”を検索」で確定する。

- ユーザー、ハッシュタグ、投稿の3つを、`type`を分けて並行に読む。`type`を付けずにまとめて読むと、`offset`が効かず続きを読めないため。ユーザーは、まだ知らない相手のサーバーのユーザーも探す（`resolve=true`）
- 結果は1つの一覧に、ユーザー、ハッシュタグ、投稿の順に、見出しを付けて並べる
  - 見出しの上には区切り線を引かず、直前の行の下の線も消して、空きで区切る。見出しの下には、左右の余白を空けた線を引く。iOS 26の連絡先アプリの見出しと同じ形
  - ユーザーとハッシュタグは、5件と「すべて見る」を出す。「すべて見る」は、その種類だけの一覧を積んで開き、スクロールで続きを読む
  - 投稿は、そのまま並べ、スクロールで続きを読む
- 3つは別々に届くので、届いたものから見せる。1つが失敗しても、ほかの結果は見せ、失敗した種類の見出しの下に失敗の表示と再試行を出す
- 0件の種類は、見出しごと出さない。全文検索のないサーバーで、毎回空の投稿の見出しを出さないため。3つとも0件なら、「見つかりませんでした」と、投稿は全文検索に対応したサーバーでだけ探せることを出す
- 投稿は、サーバーが新しい順に返すとおりに並べる。続きは`offset`で読む。`max_id`は、サーバーの中で秒単位の日時（`before:`）に直されて、同じ秒の投稿を取りこぼすため
  - 続きを読む間に新しい投稿が先頭に入ると、`offset`がずれて同じ投稿が届く。IDで重なりを除く
  - サーバーは、ミュートやブロックした人の投稿を除いてから返すので、読んだ件数が頼んだ件数より少なくても、続きがないとは限らない。続きがないと決めるのは、読んだページが0件のときだけにする
- サーバーのフィルターは当てない。公式のWebクライアントも、検索結果の投稿をフィルターのどの文脈でもない`search`で描いている
- ストリーミングも既読位置もない。引っぱると、同じ語でもう一度探す

## URLとハンドル

- httpかhttpsのURLを確定したら、`type`を付けずに`resolve=true`で読む。サーバーが相手のサーバーから投稿やプロフィールを読み込んで返す
- 投稿かユーザーが1つに決まれば、結果の一覧の上に、そのスレッドかプロフィールを開く。戻ると結果の一覧に戻る。決まらなければ、結果の一覧だけを出す
- `@user@domain`か`user@domain`の形のハンドルを確定したら、ユーザーの結果にハンドルの一致する人がいれば、結果の一覧の上にそのプロフィールを開く。同じサーバーの人は、`acct`にサーバー名が付かないため、ログインしているサーバーの名前を補って比べる
- 読み込む間は、結果の一覧に読み込み中を出す。読み込む間に、ほかのタブへ移ったり、結果の一覧の上にほかの画面を開いたりしていたら、決まっても開かない

## 最近の検索

- 確定した語を、アカウントごとにこの端末に20件まで、新しい順に残す。同じ語を確定し直したら、先頭へ動かす
- 検索欄が空のときに並べ、押すとその語で確定する
- 行を左へスワイプすると、その語を消す。「すべて消す」で全部消す
