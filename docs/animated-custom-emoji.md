# 動くカスタム絵文字

GIFやAPNGのアニメーションするカスタム絵文字を、どこで、どう動かすかについて、作者が決めたこと。

## 動かすかどうか

- 設定の「カスタム絵文字のアニメーションを再生する」で選ぶ。既定ではオフにする。アイコンのアニメーションと同じく、一覧でたくさん動くと読みにくいため
- オフのときと、視差効果を減らす設定がオンのときは、最初のコマで止めた静止画（`static_url`）を描く
- 動かすのは、一覧の投稿と通知（名前、ブーストした人の行、通知の見出し、注意書き、本文）、プロフィール（名前、自己紹介、補足情報）、編集履歴、ステータスバーの通知、投稿のメニューの「カスタム絵文字」、投稿欄の補完の候補

## 文字の中の絵文字

- 文字の中の絵文字は、静止画を同じ大きさの透明な画像に差し替えて場所だけを取り、その位置に、コマを送る層を重ねる。UILabelは埋め込んだ画像を動かせないため
- 層を置く位置は、同じ文字列をTextKit 2で並べ直して求める。リンクのタップと同じ方法で、UILabelが描いた位置と一致する
- ラベルの中に収まらない絵文字は動かさず、静止画のまま描く。切られて見えない行の絵文字と、名前のように行末で切ってぼかすラベルで、行末からはみ出す絵文字が当たる。行末のぼかしはラベルの層のマスクでかけるので、収まっている動く絵文字も文字と一緒にぼける
- 「…」で切るラベルが実際に切られているときは、最後の行の絵文字も静止画にする。UILabelが末尾を「…」に置き換えた位置はTextKit 2の並びからは分からず、動く層だけが「…」の上に残るおそれがあるため。切られているかは、行数を限らずに並べたときの行数で見る
- 同じ長さのアニメーションは、ラベルをまたいでも同じコマを出すよう、時刻で揃えて始める。同じ絵文字が並んでいても、ばらばらに動いて見えない
- 行を描き直しても、同じ絵文字を同じ位置に描くなら、層を作り直さない。アプリが裏から戻ったときは、裏に回っている間に描画のプロセスがアニメーションを外していることがあるため、層を作り直す

## コマの読み方

- アニメーション版（`url`）は、静止画とは別に、動かす場所に出たときだけ読む
- 動かすためにメモリに持つコマの画像は、長い辺が96ピクセルになるまで縮めて展開する
  - 文字の中の絵文字は、行の高さ（ふつうの本文で20〜30pt）に合わせて描く。iPhoneの画面は1ptを3ピクセルで描くので、96ピクセルあれば32ptまでは拡大せずに描け、ぼけない
  - 元の大きさのまま持たないのは、メモリを抑えるため。96ピクセルなら1コマ約36KBで、たとえば256ピクセルの絵文字を原寸で持つと1コマ約256KBになる
  - 文字サイズの設定を大きくして行の高さが32ptを超えると、拡大して描くので少しぼける。メモリとの引き換えで許している
- 全コマを1枚の画像に格子状に並べて層に1度だけ渡し、表示する範囲（`contentsRect`）だけを切り替えてコマを送る。コマごとに別の画像を差し替えるより、スクロールの引っかかりとメモリが減る。縮めて描くときに隣のコマの端がにじまないよう、コマのあいだに透明なすき間を空ける
- 0.01秒以下のコマは、ブラウザと同じく0.1秒にする。0秒や0.01秒のコマを書いたGIFが多く、そのまま使うと速く回りすぎるため
- 次の画像は動かさず、静止画で描く
  - 1コマしかない画像
  - 元の大きさが1024×1024を超えるコマ、1000を超えるコマの画像。縮める前に原寸で展開するため、他のサーバーの絵文字が小さなデータで巨大な大きさを宣言していると、メモリを使いすぎる
  - 並べた画像が8MBを超える画像
  - 既定の画像がアニメーションのコマに含まれないAPNG（最初の`fcTL`が`IDAT`より後にある）。ImageIOが最初のコマを欠いて読むため
- 並べた画像は、64MBまでメモリに持ち、あふれたら古いものから捨てる。描いている層が使っている間は、捨てても同じものを使い回し、読み直さない

## 文字の外の絵文字

- 投稿欄の補完の候補の絵文字は、画像のビューの中にコマを送る層を置く
- 投稿のメニューの印は、コマを切り出して動く画像（`UIImage.animatedImage`）にする。動く画像はどのコマも同じ長さで送るため、いちばん短いコマを1刻みにして、長いコマは刻みの数だけ繰り返して長さを近づける。メニューは開いた時点の画像で組むので、アニメーション版を読み終える前に開いたメニューでは静止画になる
