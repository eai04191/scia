# 動くカスタム絵文字

GIFやAPNGのアニメーションするカスタム絵文字を、どこで、どう動かすかについて、作者が決めたこと。

## 動かすかどうか

- 設定の「カスタム絵文字のアニメーションを再生する」で選ぶ。アイコンの「アニメーションを再生する」も同じ決まりにする
- 選ぶまでは、2つとも、サーバーのアカウントの設定「アニメーションGIFを自動再生する」（`api/v1/preferences`の`reading:autoplay:gifs`）に従う。Mastodonのwebでは、この1つの設定でアイコンとカスタム絵文字の両方を切り替えるため
  - 設定は端末に1つで、サーバーの値はアカウントごとに違う。表示しているアカウントの値に従う。窓を分けて別のアカウントを開いているときは、最後に表示を始めたアカウントの値になる
  - サーバーの値は読むたびにアカウントごとに覚え、表示を始めるときは覚えた値で描いて、読み直した値が違えば描き直す。起動のたびに既定から始めて、読めたところで動き出さないようにするため。覚えた値がなく、読めないあいだは、Mastodonの既定と同じく動かさない
  - 「投稿の見た目」を既定に戻すと、選んだ値を忘れて、サーバーの値に従う形に戻る
- 絵文字ピッカーと、ビューアで開いた絵文字は、この設定によらず動かす。端末の設定には従う（ビューアは[画像の読み込み](image-loading.md)の「ビューアで動く画像」）
- オフのときと、端末の「視差効果を減らす」がオンか「アニメーション画像を自動再生」がオフのときは、最初のコマで止めた静止画（`static_url`）を描く。アイコンのアニメーションも同じ。表示している間に端末の設定を変えたら、すぐに従う
- 動かすのは、タイムラインの投稿と通知（名前、ブーストした人の行、通知の見出し、注意書き、本文）、プロフィール（名前、自己紹介、補足情報）、編集履歴、ステータスバーの通知、投稿のメニューの「カスタム絵文字」、投稿欄の補完の候補

## 文字の中の絵文字

- 文字の中の絵文字は、静止画を同じ大きさの透明な画像に差し替えて場所だけを取り、その位置に、コマを送る層を重ねる。UILabelは埋め込んだ画像を動かせないため
- 層を置く位置は、同じ文字列をTextKit 2で並べ直して求める。リンクのタップと同じ方法で、UILabelが描いた位置と一致する
- ラベルの中に収まらない絵文字は動かさず、静止画のまま描く。切られて見えない行の絵文字と、名前のように行末で切ってぼかすラベルで、行末からはみ出す絵文字が当たる。行末のぼかしはラベルの層のマスクでかけるので、収まっている動く絵文字も文字と一緒にぼける
- 「…」で切るラベルが実際に切られているときは、最後の行のうち、「…」に置き換わるかもしれない絵文字を静止画にする。UILabelが末尾を「…」に置き換えた位置はTextKit 2の並びからは分からず、動く層だけが「…」の上に残るおそれがあるため。切られているかは、行数を限らずに並べたときの行数で見る
  - UILabelは折り返したあとで最後の行の末尾だけを置き換えるので、末尾で切るときは、絵文字の右端に「…」の幅を足しても行に収まる絵文字は、並べた位置のまま残る。それより行末に近い絵文字だけを止める。「…」の幅は、文字列の中でいちばん大きい文字で測る
  - 先頭や中ほどで切るとき、右から左に書く文字を含む段落（画面が左から右でも、アラビア語やヘブライ語の段落は「…」が左の端に入る）、左寄せでないときは、置き換えで行の中の位置が動くので、最後の行の絵文字をすべて止める
- 編集履歴で足したり消したりした絵文字は、絵文字の画像そのものの描き方を変える。差分の緑や赤の地と取り消し線は絵文字の画像の下に描かれ、背景まで塗った不透明な絵文字では隠れるため
  - 消した絵文字は薄く描いて、下の赤い地と取り消し線を透かし、動かさない。今の版にない絵文字なので
  - 足した絵文字は動かし、動く層の上に、地と同じ緑の層を、絵文字の描かれている画素にだけ重ねる。透明な部分にも重ねると、下の地と重なってそこだけ濃くなるため。動かさないときは、静止画の画素に同じ緑を重ねる
- 同じ長さのアニメーションは、ラベルをまたいでも同じコマを出すよう、時刻で揃えて始める。同じ絵文字が並んでいても、ばらばらに動いて見えない
- 行を描き直しても、同じ絵文字を同じ位置に描くなら、層を作り直さない。アプリが裏から戻ったときは、裏に回っている間に描画のプロセスがアニメーションを外していることがあるため、層を作り直す

## コマの読み方

- サーバーは、絵文字ごとに元の画像（`url`。動くことがある）と動かない版（`static_url`）を配る。動くかどうかは、元の画像を読むまで分からない
- 動かす場所は元の画像だけを読み、動かない絵文字も、その最初のコマを静止画として描く。動かさない場所は動かない版だけを読む。1つの絵文字のために2つの画像を読まないため
  - 文字の中の絵文字と投稿のメニューは、設定と端末の設定の両方が許すときに元の画像を読む
  - 絵文字ピッカーは、設定にも端末の設定にもよらず元の画像を読む。投稿欄の補完の候補とステータスバーの通知のリアクションは、設定がオンなら、端末の設定によらず元の画像を読む。どれも、表示している間に端末の設定が変わったら、読み直さずに従うため
  - 文字の中の絵文字は、描く文字列を作るときに設定から決める。設定がオンでも絵文字を動かさないラベル（プロフィールの固定された投稿の棚、プロフィールの編集の名前）に出す文字列だけ、動かない版で描く
  - 同じURLの静止画とアニメーションを同時に求められたら、1回の通信を分け合い、そのデータから両方を作る
  - 届いた画像がどの絵文字のものかは、元の画像と動かない版の両方のURLで見る
- 元の画像が大きすぎて動かせないと分かったら、そのときは最初のコマを静止画として描き、幅と高さとコマの数を端末に残して、次に起動したときからは動かす場所でも動かない版を読む
  - 分かった起動の間は、元の画像の最初のコマで描き続ける。そこで動かない版に切り替えると、読み終えるまで絵文字が消えるため。アニメーションは読み直さない
  - 残すのは大きさで、動かせるかの判断は残さない。引くたびに今の上限に当てる
  - 残すのは大きすぎて動かせなかった元の画像だけで、1,000件まで。超えたら古いものから消す
  - 大きすぎて動かせない元の画像は、端末に置かない（[画像の読み込み](image-loading.md)の「端末に残すカスタム絵文字の画像」）
- 動かすためにメモリに持つコマの画像も、静止画も、既定では高さが96ピクセルになるまで縮めて展開する
  - 文字の中の絵文字は、行の高さ（ふつうの本文で20〜30pt）に合わせて描く。iPhoneの画面は1ptを3ピクセルで描くので、96ピクセルあれば32ptまでは拡大せずに描け、ぼけない
  - 幅は縦横の比で決まるので、長い辺ではなく高さで縮める。長い辺で縮めると、横長の絵文字は高さが足りずにぼける。極端に横長な絵文字でメモリを使いすぎないよう、幅は高さの8倍までにする
  - 元の大きさのまま持たないのは、メモリを抑えるため。96ピクセルなら1コマ約36KBで、たとえば256ピクセルの絵文字を原寸で持つと1コマ約256KBになる
- 絵文字だけの本文、カスタム絵文字の倍率、文字サイズの設定、絵文字ピッカーの枠の大きさで、既定の高さより大きく描くときは、描く高さで読み直す
  - 同じURLは大きさごとに分けず、1枚だけ持つ。描いた中で一番高い高さで読んだ1枚を、小さく描く場所でも縮めて描く。読み直している間は、持っている画像で描く
  - 持っている画像の1.1倍の高さまでは、読み直さずに拡大して描く。少し大きさの違う場所で描くたびに読み直さないため。初めて読むときも、96ピクセルの1.1倍までなら96ピクセルで読む
    - 1.1倍は、サーバーの絵文字40個の拡大した見え方の誤差をFLIPで測って決めた。誤差は拡大率にほぼ比例して増え、境目はなかったので、拡大で増える誤差を、ぴったりの高さで描かずに縮めたり少し拡大したりする描き直しで避けられない誤差（2%拡大したときの誤差）の1割までに抑える割合にした
  - 元の画像より大きくは読まない。拡大してもぼけは消えないため。元の大きさで読んだ画像は、それより大きく描いても読み直さない
  - 静止画は1枚1024×1024ピクセル分（4MB）までにする。1枚で静止画のキャッシュの上限（32MB）を超えると、入れたそばから捨てられて読み直し続けるため
  - 動くコマは、描く高さで並べた画像が8MBを超えるなら、動きを止めずに、収まる中で一番高く読む。96ピクセルでも超えるものは、下のとおり動かさない
  - 持っている画像より高く読み直す通信は、質を上げる通信として送る（[ネットワーク](network.md)）。送れないときは、持っている画像を拡大して描く。初めて読む通信は、高く読んでも通信の中身は同じなので、行に描く通信として送る
  - 投稿欄の補完の候補とメニューのアイコンは、既定の高さで読む
- 全コマを1枚の画像に格子状に並べて層に1度だけ渡し、表示する範囲（`contentsRect`）だけを切り替えてコマを送る。コマごとに別の画像を差し替えるより、スクロールの引っかかりとメモリが減る。縮めて描くときに隣のコマの端がにじまないよう、コマのあいだに透明なすき間を空ける
- 0.01秒以下のコマは、ブラウザと同じく0.1秒にする。0秒や0.01秒のコマを書いたGIFが多く、そのまま使うと速く回りすぎるため
- 次の画像は動かさず、静止画で描く
  - 1コマしかない画像
  - 元の大きさが1024×1024を超えるコマ、1000を超えるコマの画像。縮める前に原寸で展開するため、他のサーバーの絵文字が小さなデータで巨大な大きさを宣言していると、メモリを使いすぎる
  - 並べた画像が8MBを超える画像
  - 既定の画像がアニメーションのコマに含まれないAPNG（最初の`fcTL`が`IDAT`より後にある）。ImageIOが最初のコマを欠いて読むため
- 並べた画像は、64MBまでメモリに持ち、あふれたら古いものから捨てる。描いている層が使っている間は、捨てても同じものを使い回し、読み直さない

## 絵文字ピッカーの小さい静止画

- 絵文字ピッカーは、静止画がメモリにない絵文字を、静止画が届くまで小さい静止画で描き、届いたらすぐ差し替える。速く流したときに、端末に置いた画像を読んで展開するのを待って、枠が空いたまま見えないため。iPhone 16 Proで約6000個を速く流すと、静止画が出るまでに中央で約0.5秒かかった
- 小さい静止画は、展開済みの画素をLZ4で圧縮して1つのファイルに並べ、メモリに写して読む。描くときに、画像の形式の展開もファイルの読み出しも待たない。LZ4にしたのは、描くたびにメインスレッドで展開するため。fedibird.comの6129個をMacで測ると、非圧縮の58%の大きさで、1つを1.4µsで展開できた（LZFSEは48%で7.4µs、zlibは45%で14.5µs）
- 高さは32ピクセル。好みで決まる値なので、チューニングで変えられる。変えると作り直す
- 静止画を展開したときに作って足す。一度も表示していない絵文字の分は、絵文字ピッカーを開いていない間に、端末に置いた画像から裏で作る。絵文字ピッカーを開いたら止める。通信はしない
- 端末に残しているすべてのサーバーの絵文字のリストから外れたものは、裏で作るときに消す
- 使うのは絵文字ピッカーだけ。タイムラインと投稿欄の補完の候補では使わない
- 最初のコマが透明な絵文字は、小さい静止画も透明になる。もとの静止画も同じで、動き出すまで空いて見える

## 文字の外の絵文字

- 投稿欄の補完の候補と、絵文字ピッカーの絵文字は、画像のビューの中にコマを送る層を置く
- 投稿のメニューのアイコンは、コマを切り出して動く画像（`UIImage.animatedImage`）にする。動く画像はどのコマも同じ長さで送るため、いちばん短いコマを1刻みにして、長いコマは刻みの数だけ繰り返して長さを近づける。メニューは開いた時点の画像で組むので、アニメーション版を読み終える前に開いたメニューでは静止画になる
