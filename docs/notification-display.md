# 通知の見せ方

通知タブの行に何をどう出すかで、作者が決めたこと。

## 枠と中身

- 投稿のセルと通知のセルは、何を主役にするかが違うため、外側の枠を分ける。投稿のセルは投稿した人が主役、通知のセルは誰が何をしたかが主役
- 投稿の中身（本文、注意書き（CW）の折りたたみ、メディア、投票、リンクカード、引用、編集済みのアイコンなど）は、投稿のセルと通知のセルで同じ部品を使う。通知の側では、種類ごとに、どの部品を出すかと、控えめな色で出すかを決める
- 投稿の中身に部品を足すときは、下の表のどの通知で出すかも合わせて決める

## 種類ごとの見せ方

| 通知 | 見せ方 |
|---|---|
| メンション、通知をオンにした人の投稿、引用 | ホームの投稿と同じ見た目にし、その上に「からのメンション」のような、誰が何をしたかの行を1行足す |
| お気に入り、ブースト、ブーストした投稿や引用した投稿の編集 | 誰が何をしたかの行を主役にし、対象の投稿を再掲する。本文は控えめな色で出し、メディアは小さなサムネイルを1列だけ出す。投票とリンクカードは出さない |
| 投票の終了 | 再掲の形に、投票の部品を結果の形で足す。通知の目的が結果を知ることのため |
| フォロー、フォローリクエスト、種類を知らない通知 | 誰が何をしたかの行だけを出す |

## 注意書き（CW）

- 再掲する投稿に注意書きがあるときも、投稿のセルと同じ部品で、注意書きを出して本文を畳む。押すと開く

## まとめて表示する

同じ投稿へのお気に入りやブースト、続けて届いたフォローを1行にまとめる。Mastodonのwebに合わせる。

- 通知はAPI v2（`GET /api/v2/notifications`）で読み、まとめるのはサーバーに任せる。どの端末で見ても同じまとまりになり、まとまりに入るだけの通知でページが埋まって行が増えないことがないため
- まとめる種類は、webと同じく、お気に入り、ブースト、フォローの3つにし、`grouped_types[]`で渡す。サーバーがまとめる種類を増やしても、知らないまとめ方の行を出さないため。まとめる範囲（お気に入りとブーストは同じ投稿ごと、フォローは全部で1つ）と時間の幅（最長12時間）は、サーバーが決めたとおりにする
- v2のないサーバーのために、v1で読む仕組みは作らない。v2はMastodon 4.3から使える
- 2人以上のまとまりでは、誰が何をしたかの行の上に、アイコンを新しい人から最大8個並べる。誰が何をしたかの行は、最も新しい人の名前だけを出し、「Aさんとほか3人がお気に入りしました」のようにする。1人のまとまりは、まとめない通知と同じ見た目にする
- 日時は、まとまりの中で最も新しい通知のものを出す
- 「ほか3人」を押すと、[account-list.md](account-list.md)の人の一覧を開く。お気に入りではその投稿をお気に入りした人、ブーストではブーストした人、フォローでは自分のフォロワーの一覧にする。webと同じく、まとまりに入った人だけでなく全員の一覧になる。並べたアイコンを押すと、その人のプロフィールを開く
- 行のそのほかの場所を押したときは、まとめない通知と同じく、対象の投稿のスレッドを開く
- ストリーミングで届いた通知の`group_key`と同じまとまりが手元にあれば、人数を1つ足し、その人をアイコンの先頭に足して（8個を超えたら一番古い人を外す）、行を一番上へ移す。すでにアイコンに並んでいる人なら、足さずに移さない（お気に入りを外して付け直したときなど）。手元になければ新しい行にする。まとめない種類の通知は、届いた`group_key`を使わず、RESTと同じ`ungrouped-<通知のID>`に置き換えて1件で1行にする。`grouped_types[]`はRESTにしか効かず、ストリーミングでは、まとめない種類にもまとめるための`group_key`が付くため。置き換えないと、補完で同じ通知が2行になり、削除でほかの通知まで消える
- 行を一番上へ移すのは、操作によらない変化なので、[vision.md](vision.md)の「一覧の動き」のとおり動かさず、読んでいる行の位置を保つ。元の場所の行は消し、一番上には新着と同じく積む
- 補完や続きの読み込みで、手元にあるまとまりと同じ`group_key`のまとまりが届いたら、1行にまとめる。人数とアイコンと日時は足し合わせず、まとまりの最も新しい通知（`most_recent_notification_id`）が新しいほうの値を使い、行もそちらの位置に置く。サーバーは、読んだ範囲の上限より古い、そのまとまりの通知を全部数えて返すため、新しいほうの値が古いほうを含む
- 未読の数は、webと同じく、まとまりを1件として数える。並んだ行の数と合わせるため
- 削除は、まとまりごとに消す（`POST /api/v2/notifications/:group_key/dismiss`）
- コンテキストメニューの関連するユーザーには、アイコンに並べた人を出す
- ステータスバーの通知は、まとめずに1件ずつ流す
