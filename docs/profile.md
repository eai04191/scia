# プロフィール

プロフィール画面の見せ方で、作者が決めたこと。

## プロフィールを開くまで

本文のメンション、自己紹介のリンク、リンクのメニューの「プロフィールとして開く」、自分のプロフィール、ほかのアプリからのURLでは、相手を探してから開くので待つことがある。待っている間の振る舞いは、どの経路でも揃える。経路を足すときも同じにする。

- 待っている間に別のプロフィールを開こうとしたら、前のものは止め、後から押したものだけを開く。同じメンションを2回タップしても、1枚だけ積む。アイコンや通知の送った人のように待たずに開くときも、待っているものを止める
- 待つ間にタブを移ったり、戻ったり、別の画面を開いたり、ビューアやシートのように上に重ねたりしたら、見つかっても積まず、失敗も知らせない。見ていないタブや重ねた画面の裏に覚えのない画面を積まず、開く先をこちらで移して画面を飛ばさないため。届く前に押した画面へ戻っていれば、そのまま積む
- 探すのが長引いたら、「取得中」のチップと「操作の状況」の行を出す。すぐ見つかったときに一瞬だけ出入りしないよう、少し待ってから出す。行から止めたら、見つかっても開かない
- ほかのアプリから開くときは、探し始める前にホームへ切り替える。探し終えてから切り替えると、待つ間にほかのタブへ移った人をホームへ戻してしまうため
- ユーザーのメニューのメンションとハンドルのコピーも、相手を探すのを待つ間に選び直したら、後から選んだ相手だけを使う。投稿欄と文字のコピーは見ている画面によらないので、待つ間に画面を移っても使う

## ヘッダー画像

添付ファイルのサムネイルは、中身を見分けるための縮小版で、ビューアで全体を見られるので、並べ方に合わせて切り抜く。ヘッダー画像はそれと違い、作者が枠を想定して作り、そのまま飾りとして見せるものなので、次のように扱う。

- ヘッダー画像は、作者が想定した比率（Mastodonのweb版が切り抜く3:1や、Sciaが編集で勧める3:2など）で作られているので、その比率を尊重する。画面の上端まで見せるために画像を切り抜いたり拡大したりしない
- 3:1の画像は、ナビゲーションバーの高さの分だけ上げ、ステータスバーのすぐ下から置く。ナビゲーションバーのボタンは画像の上に浮かせる
- 3:1より縦に長い画像は、3:4まで本当の高さで見せる。下端は3:1の画像と同じ位置のまま上へ広げ、画面の上端に届いたら下へ広げる
- 切り抜くのは、3:1より横に長い画像の左右と、3:4より縦に長い画像の上下だけにする。3:4で止めるのは、ヘッダーが画面を占めすぎないため
- 本物の画素で届かないステータスバーの帯だけを、折り返してぼかしたもので埋める。作り物の部分を広げないため、一番上から引っぱっても画像は止め、拡大して埋めない

## 自分のプロフィールの編集

- 自分のプロフィールでは、フォローのボタンの場所に「プロフィールを編集」を出し、押すとシートで編集画面を開く
- 編集するのは、表示名、自己紹介、補足情報、アイコン、ヘッダー画像、フォローを承認制にするか、botのアカウントとして示すか。検索やディレクトリへの掲載などの公開の設定と、投稿の既定値は、ここでは扱わない
- 表示用のHTMLではなく、サーバーが返す平文（`source`）を編集させる。リンクや絵文字のHTMLは、保存したあとにサーバーが作る
- 表示名、自己紹介、補足情報では、投稿欄と同じ補完と絵文字のシートでカスタム絵文字を入れられる。サーバーは自己紹介と補足情報の内容を同じ整形にかけてメンションとハッシュタグをリンクにするので、`@`と`#`の補完はこの2つで効かせる。表示名と補足情報の名前はカスタム絵文字だけを読むので、絵文字だけを補完する。入力中の欄では、カスタム絵文字は`:shortcode:`の文字のまま見せる
- 補足情報の行は、表の編集の状態で消したり並べ替えたりする。サーバーの上限の数に達したら、追加の行を消す
- 表示名、自己紹介、補足情報の数の下に、サーバーの上限に対する文字数や行数を出し、超えたら赤くして保存させない。上限は、Mastodonが`api/v2/instance`で返す値を使い、返さない4.6.0より前のMastodonでは、そのころの決まった値を使う
- 承認制とbotのスイッチの説明は、区切りの下にまとめず、それぞれのスイッチの名前の下に小さく出す
- 変えたものがあるのに閉じようとしたら（キャンセルのボタンと、下へスワイプする操作）、捨ててよいか確かめる。保存できなかったときは、書いたものが届かずに失われるので、アラートで知らせ、書いたものを残す

### アイコンとヘッダー画像の切り抜き

- APIのドキュメントとサーバーには、比率の決まりがない。Mastodonのweb版の編集画面（4.6.0から）は、アイコンを1:1、ヘッダー画像を3:1に切り抜いてから送る
- 写真を選んだら、送る枠に切り抜く画面を出す。ピンチと移動で、枠に入れる部分を選ぶ。枠の外の画像も暗くして見せ、枠の外から触れても動かせる
- アイコンは正方形に切り抜く。Mastodonは400×400に中央で切り抜いて保存するので、選んだ部分がそのまま使われるよう、こちらで切り抜いて400×400以下で送る。枠は、一覧のアイコンの形の設定（丸か角の丸い四角）で示す
- ヘッダー画像は、切り抜く画面の下の切り替えで3:2か3:1を選び、既定は3:2にする。Sciaでは3:2を勧める。3:1より綺麗に見せられ、多くのアプリが3:2に近い枠で見せていて、Mastodonの作者（Gargron）も3:2を挙げているため。3:1はweb版の枠に合わせたい人のために残す
- サーバーはヘッダー画像を切り抜かず、1500×500と同じ画素数に収まるまで、比率を保って縮めて保存する。それを超えない大きさで送る（3:2なら1060×707まで）
- 編集画面のヘッダー画像の見本は、見せている画像の比率で出す。3:1より横に長いものと3:2より縦に長いものはその比率で切り、画像がなければ3:2の枠を出す
- 切り抜いた画像は、透過があればPNG、なければJPEGで送る
- GIFは、動きを残すため、切り抜かずに元のファイルのまま送る（web版と同じ）。アイコンはサーバーが中央で正方形に切り抜き、ヘッダー画像は元の比率のまま保存される
- 画像のメニューは、写真を選ぶ、変更を取り消す（選んだあとや削除を選んだあと）、削除（設定しているとき）。削除はほかの項目を保存したあとに、別のAPIで送る。Mastodonは設定していない画像にも`missing.png`の既定の画像のURLを返すので、そのURLなら設定していないとみなす
