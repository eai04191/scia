# タブ

タブバーに並べるタイムラインと切り替えタブで、作者が決めたこと。

- タブバーには、ホーム、通知、ローカル、連合、リストなどのタイムラインから、使う人が選んだものを直接並べる。選ぶことと並べ替えは設定で行う。リストはアカウントごとに違うため、並びもアカウントごとに持つ
- 設定は、長押しのメニューの並びの設定（[menus.md](menus.md)の「並びの設定」）と同じく、1本のリストに項目と境目の行を並べ、項目ごとにスイッチで表示と非表示を切り替える。境目より上の項目はタブに並べ、下の項目は、タブバーの最後の1つの切り替えタブにまとめる。表示数を数で入れず、境目を動かして決める。メニューの設定と同じ部品と操作で済み、表示数と並びを別々に合わせる手間がないため
- 既定の並びは、切り替えタブを使わず、ホーム、ローカル、連合、通知を直接並べる
- 有効な項目が最後の1つになったら、そのスイッチを切れなくする。タブバーを空にできないため
- 切り替えタブは、押すと最後に選んだタイムラインを開き、見出しのメニューから中身を切り替える。UIKitのタブバーにはタブを押してメニューを出す仕組みがなく、タブの上に独自の部品を重ねると壊れやすいため。最後に選んだタイムラインは、アカウントごとに起動し直しても覚えておく
- 切り替えタブの名前とアイコンは、今開いているタイムラインのものにする。押したときに何が開くかを、タブを見れば分かるようにするため。切り替えられることは、見出しのメニューの印で示す
- 切り替えタブで切り替えても、前に見ていたタイムラインは、読み込んだ投稿とスクロール位置をメモリに残し、戻ったらそのまま続きから見せる
- 有効にしたタイムラインは、タブに並べていても切り替えタブに入れていても、見ていない間もストリーミングの購読を続ける。購読をやめるのは、設定で無効にしたとき
- ホームを無効にしているときは、URLなどでプロフィールを開くと、今見ているタブに開く。ほかに開ける場所がないため
- サーバーがローカルや連合のタイムラインを閉じていても（`configuration.timelines_access`）、選べるままにし、読み込みに失敗したときの表示をそのまま出す
- 通知も、ほかのタイムラインと同じく切り替えタブに入れられる。そのときは、切り替えタブのバッジに通知の未読の数を出し、ステータスバーの通知を押したら、切り替えタブを通知に切り替えて開く

## ブックマークとお気に入り

ブックマークした投稿とお気に入りした投稿の一覧も、タブに置ける項目にする。どちらも同じ決まりで作る。

- 既定では無効にし、切り替えタブの境目より下に置く。有効にすると切り替えタブに入る。たまに見る一覧なので、ふだん並べる4つを押しのけないため
- 並びは、サーバーが返すとおり、ブックマークした順、お気に入りした順にする。投稿の日時やIDの順ではない。続きは、APIの決まりどおり、応答の`Link`ヘッダーの`next`から読む
- 流れてくるストリームがないので、購読しない。新しくブックマークやお気に入りをした投稿は、次の2つで一覧に入れる
  - アプリの中で付けたら、サーバーが受け付けたところで一覧の先頭に入れる
  - タブで一覧を開くたびと、一覧を開いたままアプリに戻ったときに、最新の1ページを読み、手元の先頭より新しい分を先頭に足す。ほかの端末やwebで付けた分を拾うため。手元の先頭が最新の1ページに見つからなければ、間が埋まらないので、一覧を読んだページで置き換える
- 一覧の中で外しても、行はすぐには消さず、印を外したまま残す。押し間違えたときに、その場で付け直せるようにするため。ほかのタブへ移ったとき（切り替えタブでほかの一覧に切り替えたときも含む）に、外した行を消す。見ていないときに消すので、動かさない。スレッドやビューアを上に重ねたときは消さない。戻る途中の一覧や、閉じる動きの行き先の行が、目の前で消えないようにするため
- 消すのは、外すのをサーバーが受け付けた行だけにする。結果を待っている間に消すと、外すのに失敗して印を戻しても、行が戻らないため。一覧を見ていない間に、ほかのタブで外して受け付けられた行は、その場で消す
- 先頭に足すときは、一番上にいても新着のように追従せず、読んでいる行の位置を保つ
- サーバーのフィルターは、公式のWebクライアントと同じく、ホームと同じ文脈（`home`）で当てる。ただし「隠す」に一致した投稿も隠さず、警告で畳む。自分で残した投稿を、一覧から黙って消さないため
- 既読位置はサーバーに保存せず、未読の数も出さない

## リスト

自分のリストのタイムラインも、タブに置ける項目にする。リストの作成と管理は別の作業で、ここではMastodonのwebなどで作ったリストを読んで流す。

- リストの一覧（`GET /api/v1/lists`）は、起動したときと、アプリに戻ったときに読み、タブの並びに反映する
  - まだ並びにないリストは、無効にして並びの末尾に足す。ブックマークやお気に入りと同じく、使う人が選んだものだけを読み、購読するため
  - サーバーにもうないリストは、並びから外す。読めなかったときは、並びを変えない
  - 名前が変わったリストは、並びの名前を書き換える。タブバーと一覧の見出しの名前は、起動し直すまで前の名前のまま残す
- 並びには、リストのIDと名前を残す。起動してすぐ、リストの一覧を読む前から、タブの名前を出せるようにするため
- ホームやローカルと同じく、投稿のIDの順に並べ、ストリーミングの`list`で流す。見ていない間も購読を続け、切れていた間は補完する
- サーバーのフィルターは、ホームと同じ文脈で当てる。Mastodonのフィルターの`home`の文脈は、ホームとリストに当てるものだから
- 既読位置はサーバーに保存しない。markersはホームと通知にしかないため

## フォローしているハッシュタグ

フォローしているハッシュタグのタイムラインも、リストと同じ決まりでタブに置ける項目にする。ハッシュタグをフォローする操作は別の作業で、ここではフォロー済みのハッシュタグを読んで流す。

- フォローしているハッシュタグの一覧（`GET /api/v1/followed_tags`）は、リストと同じく、起動したときと、アプリに戻ったときに読み、タブの並びに反映する。一覧は`Link`ヘッダーで続きを読み、最後まで読み切ってから反映する。途中で読めなければ、並びを変えない
  - まだ並びにないハッシュタグは無効にして末尾に足し、フォローをやめたハッシュタグは並びから外す
- 同じハッシュタグかどうかは、サーバーと同じ決まりでそろえた名前（大文字と小文字、全角と半角などをそろえる）で見る。並びには名前を残し、タブの名前は`#`を付けて出す
- 投稿のIDの順に並べ、ストリーミングの`hashtag`で流す。見ていない間も購読を続け、切れていた間は補完する
- サーバーのフィルターは、公開タイムラインと同じ文脈（`public`）で当てる。フィルターの文脈に、ハッシュタグのタイムラインだけのものはないため
- 既読位置はサーバーに保存しない
