# 長押しのメニュー

投稿や通知を長押しして出すメニューの組み方と、使う人がその並びを変える設定について、作者が決めたこと。投稿欄の＋のボタンも、ここの「並びの設定」と「あとから項目が増えたとき」と同じ仕組みで並べる。投稿欄の＋の決まりは[compose.md](compose.md)の「＋のメニューとボタンの行」にある。

## メニューの単位

- メニューは、投稿やユーザーのような対象ごとに1つずつ持つ。いまあるのは投稿、ユーザー、リンク、ハッシュタグのメニューで、ほかに操作が増えた対象は、その時点でメニューを足す
- 本文のリンクを長押ししたときは、行き先の対象のメニューを出す。URLはリンクのメニュー、ハッシュタグはハッシュタグのメニュー、メンションはユーザーのメニューで出し、見出しにURL、`#名前`、`@acct`を置く。見出しで対象が分かるので、中身が1つでもサブメニューにせず並べる。出す項目がなければメニューを出さない
- URLを開く項目は、どのメニューでも同じ名前で同じ動きにする。「ブラウザで開く」は、リンクをタップしたときと同じく開く場所の設定に従う。「既定のブラウザで開く」と「アプリ内のSafariで開く」は、設定にかかわらずその場所で開く。この2つは開く場所の設定と重なるため、既定では隠す。アプリ内のSafariはhttpとhttps以外のURLを開けないため、そのURLでは「アプリ内のSafariで開く」を押せないようにし、ほかの場所で開き直さない
- リンクのメニューには、「ブラウザで開く」と同じ動きになる「開く」を置かない。ハッシュタグはアプリに開く画面がまだないため、開く項目はサーバーのハッシュタグのページを開くものだけにする
- 投稿のメニューには、「投稿したユーザー」「ブーストしたユーザー」「メンションされたユーザー」のように、関係するユーザーの項目を置ける。その項目は、そのユーザーのユーザーのメニューを、`@acct`のサブメニューとして出す。メンションされたユーザーのように何人もいる項目は、人数分のサブメニューを並べる。同じユーザーが2つの項目に当たるときは、先に出る項目で1度だけ出す
- 入れ子は1段までにする。ユーザーのメニューには、ほかの対象の項目を置かない。設定画面が対象ごとの1階層で済み、メニューが際限なく深くならない
- 通知のメニューは、対象の投稿の投稿のメニューで組む。通知した人は、投稿のメニューの「通知したユーザー」の項目で出す。この項目は通知でだけ出る。投稿のない通知（フォローなど）では、投稿を必要としない項目だけを出す
- ユーザーのサブメニューの中身が1つで、「その他」に何もないときは、サブメニューにせず「@acctのプロフィール」のように直接並べる。1回余計に押す手間を省く

## 並びの設定

- 設定画面は、対象ごとのメニューを1つの画面で並べ替える。どの画面も1階層にする
- 並びは1本のリストで、項目と区切り線と「その他」の境目の行を並べる。項目も区切り線もドラッグで動かす
- 区切り線は項目として置き、足したり消したりできる。区切り線と区切り線の間が、メニューの1つのまとまりになる
- 「その他」の境目より下の項目は、メニューの「その他」のサブメニューに入る。削除のように、要るけれど誤って押したくない項目を置く場所にする。「その他」は中身が1つでも開かずにサブメニューのまま出し、空なら出さない
- 項目ごとにスイッチで表示と非表示を切り替える。非表示にした項目もリストの同じ場所に残し、どこにあったか探さずに戻せるようにする。見たくない項目は、下へ動かしてからスイッチを切る
- 「その他」に入れたユーザーの項目は、「その他」→「@acct」→ユーザーのメニューの2段になる。使う人が選んだ置き方なので制限しない

## あとから項目が増えたとき

- 保存するのは、隠した項目も含めた全項目の並びと、項目ごとの表示と非表示にする。使う人が隠した項目と、まだ知らない新しい項目を見分けるため
- 新しい項目は、既定の並びでその項目の直前にある項目（区切り線は数えず、「その他」の境目は数える）の、保存した並びの中での位置の後ろに差し込む。既定で「その他」の境目のすぐ後ろにある項目は、保存した並びでも「その他」の中の先頭に入る
- 新しい項目の表示と非表示は、項目ごとの既定に従う。一律に隠すと、機能を足してもメニューに出ず、足したことに気づけないため
- 保存した並びにある、なくなった項目は読み込むときに捨てる
- 既定の並びは、設定を足す前のメニューと同じ並びにする。メンションされたユーザーのように、足す前のメニューになかった項目は既定で隠す
