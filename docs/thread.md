# スレッド

返信のある投稿を一覧でどう見せるかと、スレッドの画面をどう作るかで、作者が決めたこと。一覧のラベルと線、スレッドの画面は、同じ部品を使うので一緒に作る。

## 一覧の返信のラベル

- 返信の投稿には、本文の上に、返信先を示す小さいラベルを1行出す。「↩ @userへの返信」のように、返信先をハンドルで書く
- 返信先のハンドルは、`in_reply_to_account_id`を投稿の`mentions`と照らして決める。ラベルのために通信しない。返信先のアカウントが`mentions`にないとき（返信からメンションを消したときなど）は、ハンドルを書かずに「返信」とだけ出す
- 返信先が投稿者自身なら、続けて書いた投稿として「続き」と出す
- 返信先が自分なら「自分への返信」と出し、記号と文字をアプリの色で描いて、自分への返信に一覧の中で気づけるようにする
- 固定された投稿とブーストの行では、名前の上にそのことを示す行を出すため、返信のラベルは出さない
- ラベルの行の高さは、受け取った時点で決まる。後から届くもので高さを変えない
- ラベルは押せる見た目にしない。返信の行は行全体でスレッドを開くので、ラベルだけを押せるようにする必要がない

## 線

- 一覧で、返信先の投稿がすぐ下の行にあれば、2つの行のアイコン同士を縦の線でつなぐ
- 線は、一覧とスレッドの画面で同じ部品を使う
- ストリーミングで、返信先の行の真上に返信が挿入されたら、返信先の行も描き直して線をつなぐ。線を足しても行の高さは変えない

## スレッドを開く

- 投稿の行全体の押下で、その投稿のスレッドを開く。優先度は一番低くし、本文のリンク、名前の行、添付ファイル、リンクカードなど、行の中で押下を受けるものが先に受ける
- 通知の行も、投稿を含む通知（メンション、お気に入り、ブースト、投票の終了、編集など）なら、行全体の押下でその投稿のスレッドを開く。フォローとフォローリクエストの通知は、投稿がないため開かない
- 押した投稿を、一覧で見えていた画面上の位置から動かさずに開く。ほかの行が消え、祖先は上に、返信は下に現れる
- 押した投稿より上に並ぶ祖先が、押した位置までの高さに足りないときは、読み終えたところで最上部まで動かし、上の空きを詰める
- 画面の下端の行を押したときなど、返信が画面の外になる場合に、押した投稿を上へ寄せるかどうかは、チューニングで選べるようにする

## スレッドの並べ方

- 祖先と返信は字下げせず、すべて同じ幅で平らに並べる。短文の往復が続いても、本文の幅が細らないようにするため
- 返信は、返信先の直後に、深さ優先で並べる
- すぐ上の行が返信先なら、線でつなぎ、ラベルは出さない。返信先が離れた行にあれば、一覧と同じ返信のラベルで返信先を示す
- 押した投稿だけは、返信先がすぐ上にあってもラベルを残す。開いた時点では返信先がまだ並んでおらずラベルを出しているため、読み終えたときにラベルが消えて名前と本文が跳ねないようにする

## 開いている間の新着

- Mastodonのストリーミングにはスレッド単位のストリームがない。すでにつないでいるストリームに流れてきた投稿のうち、返信先がスレッドの中の投稿であるものを、スレッドにも足す。届くのは、フォローしている人の返信と、自分への返信に限られる。それ以外の返信は、開き直すまで出ない
- ストリームで届いた、スレッドの中の投稿の編集と削除も反映する
- 押した投稿より上に挿入するとき（祖先の投稿への新しい返信など）は、一覧と同じく、読んでいる位置を動かさない
