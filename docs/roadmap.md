# Roadmap

各項目は、agentに1タスクとして渡せる単位にしている。

Mastodon APIへの対応（A）と、それ以外の手触り、表示、検証の土台など（X）に分けて書き、2つは並行して進める。それぞれの中では上から順に進める前提で、先の項目は前の項目の成果に依存する。

## Mastodon APIへの対応

### A1: ログインとホームタイムライン

- [x] OAuthログイン（`ASWebAuthenticationSession`）とトークンのKeychain保存
- [x] ホームタイムラインの取得と表示（RESTのみ、下方向への追加読み込み）
- [x] 投稿本文のHTMLをリッチテキストに変換（リンク、メンション、ハッシュタグ、カスタム絵文字）

### A2: ストリーミング

- [x] `/api/v1/streaming`のWebSocketクライアントと、イベントのデコード
- [x] 新着の挿入ポリシー: まとめて挿入する間隔、最上部にいるときの自動追従、それ以外は新着件数の表示
- [x] 切断と復帰: 再接続と、切れていた間の投稿をRESTで埋めるギャップ処理（重複と漏れのテストつき）
- [x] markers APIによる既読位置の同期

### A3: 毎日使えるまで

- [x] 通知タブ
- [x] 投稿、返信、ふぁぼ、ブースト
- [x] 画像の表示とビューア
- [x] 複数アカウントの切り替え（一度に使うのは1アカウント）

### A4: Monaから乗り換えられるまで

Monaを開かずに1日過ごせることを完了の条件にする。終わっていない項目は、上から優先度の高い順に並べる。

- [x] プロフィール画面（投稿の一覧、フォローの状態）
- [x] 投稿へのメディアの添付と、代替テキストの入力: 選び方の仕様は[media-attachment.md](media-attachment.md)
- [ ] 本文のリンクを開く: URL、ハッシュタグに加え、メンションはプロフィールを開く
- [ ] 注意書き（CW）付きの投稿の折りたたみと展開
- [ ] サーバーのフィルターを当てる: 「隠す」の投稿は出さず、「警告」の投稿は折りたたむ
- [ ] 投票の表示と投票
- [ ] スレッド（会話）の表示
- [ ] 投稿のリンクのコピー、共有、ブラウザで開く
- [ ] ブックマーク
- [ ] 自分の投稿の編集と削除
- [ ] 編集された投稿に、編集済みの印を付ける
- [ ] リンクのプレビュー（カード）の表示
- [ ] 投稿の中の引用の表示
- [ ] ミュート、ブロック、通報
- [ ] フォローリクエストの承認と拒否
- [ ] 検索とハッシュタグのタイムライン

### A5: 想定外の応答への備え

開発者が試していないサーバーやプロキシが仕様どおりに返さなくても、壊れずに使えるようにする。守ることは[vision.md](vision.md)の「想定外の応答への向き合い方」にある。A4と並行して、上から順に進める。

- [x] 401でアカウントを消さない: トークンが本当に無効か確かめ、無効ならログインし直しを促す
- [x] 切れていた間の取りこぼしを防ぐ: 求めた件数より少なく返すサーバーでも、間の投稿と通知を取りこぼさない
- [x] 1件読めない投稿があっても一覧を出す: 読めなかった投稿や通知は「表示できない」行として並べる
- [x] エラーを種類に分けて見せる: HTMLのエラーページなどを出さず、種類ごとの文言で知らせる
- [x] ストリーミングがつながらないサーバーに備える: v1の接続先やポーリングに切り替え、切れていることを控えめに表示する
- [x] レート制限と通信の回復: 429や503では待ち、電波が戻ったらすぐやり直す
- [x] 使えない機能をセッションの間だけ止める: 既読位置の保存などが使えないサーバーで、全体を止めない
- [x] 診断の記録と「接続の状態」画面: リリース版の記録だけで原因を絞れるようにし、設定から状態を確かめられるようにする
- [x] 壊れた応答のfixture: 上の挙動をテストで押さえる

### A6: Mastodonの機能を一通り使えるまで

A4に入れていない、Mastodonのクライアントとしてできることを、上から優先度の高い順に並べる。

- [ ] 投稿に閲覧注意を付ける
- [ ] 投稿欄で、メンション、ハッシュタグ、カスタム絵文字を補完する
- [ ] 会話のミュート
- [x] フォローしたあとに、フォロワー数を読み直す
- [ ] 編集された投稿の編集履歴
- [ ] 投稿をお気に入りした人とブーストした人の一覧
- [ ] 引用して投稿する、自分の投稿を引用できる人を決める、引用の一覧
- [ ] 自分の投稿をプロフィールに固定する、外す
- [ ] 自分のプロフィールの編集
- [ ] お気に入りした投稿の一覧
- [ ] フォローとフォロワーの一覧
- [ ] 相手のプロフィールに個人用のメモを書く
- [ ] フォロワーから外す
- [ ] ミュートとブロックの一覧と解除、ドメインのブロック
- [ ] ハッシュタグのフォローと、フォローしているハッシュタグの一覧
- [ ] 投稿の翻訳
- [ ] 通知の削除
- [ ] 通知のフィルター: 知らない人からの通知を保留し、承認する
- [ ] 通知をまとめて表示する
- [ ] 投票を作って投稿する
- [ ] サーバーのお知らせを見る、リアクションする
- [ ] 投稿の言語を選ぶ
- [ ] 予約投稿

- [ ] プロフィールで注目のハッシュタグとおすすめのアカウントを設定する

## 手触りとその他

### X1: 検証の土台

- [x] スクロール位置保持のテストハーネス: 任意の件数を上に挿入したとき、基準セルの画面上の位置が変わらないことを検証するUIテストまたはユニットテストの仕組み
- [x] デバッグ用チューニングパネル: デバッグビルドでのみ表示され、値を実行中に変えられる設定画面の仕組み（項目はこの時点では空でよい）
- [x] 違和感レポート: シェイクで直前の状態ダンプ、ログ、メモを保存する仕組み

### X2: 毎日使って見つけた改善

使いながら見つけた違和感を、1つずつ直す。Mastodon APIの機能が足りないときは、「Mastodon APIへの対応」に足す。設計に関わる大きな機能は予定せず、これまでに足した、説明にならない代替テキストを隠す設定や、一覧のサムネイルを元の画質で表示する設定のような、設定や表示の細かい改善が中心になる。項目は見つけた時点でここに追加する。

- [ ] pull to refreshのストリーミング接続状況のところに他のTL取得関連も出す（ギャップ取得 ほかにもある？）
- [ ] ユーザーのコンテキストメニューに、ユーザーに対するアクションを入れる（プロフィール など）
- [ ] 投稿や通知のコンテキストメニューに、投稿や通知に対するアクションを入れる（お気に入り など）
- [ ] 投稿や通知のコンテキストメニューに、関連するユーザーをサブメニューとして入れる (@fooを展開すると「プロフィール」「ブロック」など)
- [ ] 投稿や通知やユーザーのコンテキストメニューに表示される・サブメニューで表示するものを、設定でカスタマイズできるようにする
- [ ] トランジションとAPIリクエストの点検: 画面遷移ごとにアニメーションの途中の操作で破綻しないか、タイムラインの更新で不要なリクエストを送っていないかを確かめる
- [ ] メディアのメニューにメディアの情報を表示する（解像度、サイズ、形式、フレーム数、fpsなど）
- [x] プロフィールのアイコンとヘッダー画像をタップして、ビューアで大きく見る: ビューアは開閉の起点にサムネイルのビュー（MediaTileView）を使うため、アイコンとヘッダー画像からも起点を渡せるようにする
- [x] タブバーの上に常に置く投稿欄: 1、2行の短い投稿や返信を、タイムラインを見たまま書けるようにする。書いていないときは細いカプセルにして閲覧を邪魔せず、書くときは同じバーがキーボードの上へ上がる
- [ ] インライン投稿欄の下書きを、アプリを起動し直しても残す
- [ ] インライン投稿欄のビューアで、選んだGIFを動かす: いまは最初のコマだけを出している。投稿するとgifvになるので、タイムラインのgifvと同じく音なしで繰り返す
- [ ] インライン投稿欄で読み込み終わる前に開いた動画が、読み込み後に動画のページへ作り直されるときの見え方を確かめる: 読み込みに時間のかかる動画が手元になく、テストでしか確かめていない
- [x] インライン投稿欄で5枚以上添付し、サムネイルの列が横にスクロールするときのドラッグの並べ替えを確かめる: カタログで確認済み
- [ ] インライン投稿欄で注意書き（CW）を書く: いまは全画面の投稿画面に広げたときだけ書ける
- [ ] Mac（Designed for iPad）で、投稿やチューニングのシートが出始めるまで遅いのを直す: 押してから何も出ずにもたつき、そのあとパッと出る。iPhoneでは起きない。AeroSpaceを終了しても、Releaseビルドでも変わらなかった。Time Profilerでは、シートを出す直前のSwiftUIの最初のレイアウト（`UISheetPresentationController _transitionWillBegin` → `_UIHostingView.layoutSubviews`）に120〜190msかかっていたが、それだけで説明できるかは分かっていない。次はInstrumentsのAnimation HitchesやSwiftUIのテンプレートで、押してから出始めるまでを測る
- [ ] インライン投稿欄の添付で、処理中の動画の回る表示と再生の印が重なるのを直す: 部品カタログ（`scia-debug://catalog/attachment-strip`）で見られる
- [ ] 一覧の添付ファイルで、読み込めなかったことが読み込み中と見分けられるかを確かめる: 部品カタログ（`scia-debug://catalog/media-grid`）では同じ見た目に見える。実物ではまだ確かめていない

### X3: 知らせ方を整える

操作の結果や失敗の知らせ方を、[notices.md](notices.md)の決まりにそろえる。上の4つは上から順に進める。下の3つはほかの項目に依存しない。

- [x] 知らせのチップを1つの部品にまとめ、ビューアの「写真に保存しました」、アップロードの状態、ダウンロード中を置き換える
- [ ] 「最近の失敗」の一覧を、アカウントのメニューから開けるようにする
- [ ] お気に入りとブーストの失敗を、アラートではなくタイムラインのチップで知らせる
- [ ] ビューアを閉じても保存のためのダウンロードを続け、保存は並べて落とす
- [x] プロフィールを開いたあとの読み込みの失敗を、アラートではなくフォローのボタンの場所で知らせる
- [x] ギャップの読み込みの失敗を、行の中で知らせる
- [x] 写真に保存できなかったときの文言を、種類ごとの文言にする
