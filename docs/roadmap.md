# Roadmap

各項目は、agentに1タスクとして渡せる単位にしている。済んだ項目は消す。

Mastodon APIへの対応（A）と、それ以外の手触り、表示、検証の土台など（X）に分けて書き、2つは並行して進める。それぞれの中では上から順に進める前提で、先の項目は前の項目の成果に依存する。

## Mastodon APIへの対応

### A6: Mastodonの機能を一通り使えるまで

Mastodonのクライアントとしてできることを、上から優先度の高い順に並べる。

- [ ] 絵文字のシートで、肌の色を選べる絵文字の肌の色を選ぶ
- [ ] 絵文字のシートの検索で、言葉のリストにない語でも、意味の近い絵文字を端末の中で探す
- [ ] 自分のアイコンとヘッダー画像に代替テキストを付ける
- [ ] プロフィールの公開の設定（検索に出す、ディレクトリに載せる、フォローとフォロワーを隠す）
- [ ] フォロワーから外す
- [ ] ミュートとブロックした人のリストと解除、ドメインのブロック
- [ ] 投稿の翻訳
- [ ] 個別の会話（ダイレクトメッセージ）のリスト

### 優先度が低い

ほかの項目が終わってから考える。

- [ ] プッシュ通知
- [ ] 検索の演算子（自分の投稿、メディアあり、期間）をチップで選ぶ、ユーザーのメニューの「この人の投稿を検索」
- [ ] 検索で、notestockの検索APIを使って投稿を探す
- [ ] トレンド（ハッシュタグ、投稿、リンク）
- [ ] おすすめのフォローとプロフィールのディレクトリ
- [ ] 共通のフォロワーを見る
- [ ] リンクのタイムライン: 同じリンクを共有した投稿を並べる
- [ ] コレクション
- [ ] 年間のまとめ

## 手触りとその他

### X1: 検証の土台

- [ ] CIで、警告をエラーとして扱うReleaseのビルドを行う

### X2: 毎日使って見つけた改善

使いながら見つけた違和感を、1つずつ直す。Mastodon APIの機能が足りないときは、「Mastodon APIへの対応」に足す。設計に関わる大きな機能は予定せず、設定や表示の細かい改善が中心になる。項目は見つけた時点でここに追加する。

- [ ] サーバーから提供されていないリンクカードをクライアント側で作成: 仕様は[link-card.md](link-card.md)
- [ ] TL新着投稿挿入時間を大きさに比例させる
- [ ] トランジションとAPIリクエストの点検: 画面遷移ごとにアニメーションの途中の操作で破綻しないか、タイムラインの更新で不要なリクエストを送っていないかを確かめる
- [ ] 投稿のメニューを開くとき、投稿の真ん中からガラスの板が伸びてメニューになる動きを直す
- [ ] インライン投稿欄の下書きを、アプリを起動し直しても残す
- [ ] 投稿を送っている間にも、次の投稿を書けるようにする
- [ ] 投稿欄の開閉で本文の文字を動かすとき、右から左へ書く文字（ヘブライ語、アラビア語）を含む本文でも、文字を重ねず跳ばさない
- [ ] インライン投稿欄で読み込み終わる前に開いた動画が、読み込み後に動画のページへ作り直されるときの見え方を確かめる: 読み込みに時間のかかる動画が手元になく、テストでしか確かめていない
- [ ] Mac（Designed for iPad）で、投稿やチューニングのシートが出始めるまで遅いのを直す: 押してから何も出ずにもたつき、そのあとパッと出る。iPhoneでは起きない。AeroSpaceを終了しても、Releaseビルドでも変わらなかった。Time Profilerでは、シートを出す直前のSwiftUIの最初のレイアウト（`UISheetPresentationController _transitionWillBegin` → `_UIHostingView.layoutSubviews`）に120〜190msかかっていたが、それだけで説明できるかは分かっていない。次はInstrumentsのAnimation HitchesやSwiftUIのテンプレートで、押してから出始めるまでを測る
- [ ] インライン投稿欄の添付で、処理中の動画の回る表示と再生アイコンが重なるのを直す: 部品カタログ（`scia-debug://catalog/attachment-strip`）で見られる
- [ ] タイムラインの添付ファイルで、読み込めなかったことが読み込み中と見分けられるかを確かめる: 部品カタログ（`scia-debug://catalog/media-grid`）では同じ見た目に見える。実物ではまだ確かめていない
- [ ] 投稿の行を作る処理を軽くする: プロフィールの最初の読み込みのように数件をまとめて作ると、メインスレッドが100msほど止まる
- [ ] アクションバーのブーストとお気に入りのボタンを長押しして出すメニューで、ほかのアカウントでブーストやお気に入りをする
- [ ] ユーザーのメニューの「別のアカウントで」の通報に、長押しした投稿を、そのアカウントのサーバーで探し直して添える
- [ ] プロフィール画面の「…」のメニューで、開いている間に読めた「別のアカウントで」のアカウントのアイコンを、記号から差し替える
- [ ] アップデート後の初回起動で、お知らせアカウントのそのバージョンの投稿を見せ、そこからお気に入りや返信をできるようにする

### X4: 設定画面を作り直す

継ぎ足してきた設定画面を、見た目の調整と、それ以外の設定に分けて組み直す。チューニングにある値のうち使う人が選ぶものは、設定に移す。「投稿の見た目」の決まりは[appearance.md](appearance.md)にある。

- [ ] 投稿の文字と線の色を、ダークモードと合わせて設定で選べるようにする
- [ ] メディア、リンクカード、Xの投稿の角の丸みを、ビューアの開閉の動きと合わせて設定で変えられるようにする
- [ ] 複数のメディアの並びの縦横比と最大の数、サムネイルのバッジの文字の大きさを設定で変えられるようにする
- [ ] 「投稿の見た目」に、標準・詰める・ゆったりなどのまとめて選ぶ見た目を足す
- [ ] 見た目以外の設定を、何を触るか（タイムライン、操作、投稿欄、メディア、情報）でまとめて並べ直し、検索を置く
- [ ] チューニングのうち使う人が選ぶ値（新着をまとめる間隔、最上部での追従、ギャップを読む距離、スレッドで押した投稿を上へ寄せる、投稿欄の高さと行数、絵文字のパレット、補完の候補の数、ビューアを閉じる距離と速さ）を設定に移す
