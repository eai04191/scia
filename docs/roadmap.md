## 想定外の応答への備え

Mastodonクライアントは、開発者が試していないサーバーの実装や版、手前のプロキシと話す。APIが仕様どおりに返さなくても、クラッシュせず、ログアウトもせず、読めた分は読めるようにする。M4と並行して、上から順に進める。

- [x] 401でアカウントを消さない: 資格情報を消すのは、使う人がログアウトを選んだときだけにする。401が返ったら`verify_credentials`で確かめ、それも401なら、表示中の内容とアカウントのメニュー（切り替え・追加・設定）を残したまま、ログインし直しを促すバナーを出して自動の通信を止める。ログインし直したら、同じアカウントのトークンを差し替える
- [x] 切れていた間の取りこぼしを防ぐ: ページの件数が`limit`に届かなくても読み切ったとは判断せず、0件が返ったときだけ読み切ったと判断する。`limit`を小さく丸めるサーバーで、ギャップを置かずに投稿を取りこぼさないようにする
- [x] 1件読めない投稿があっても一覧を出す: 一覧は要素ごとにデコードする。IDが読めれば「表示できない投稿」「表示できない通知」の行を出し、URLがあればブラウザで開けるようにする。IDも読めなければ外して記録する。表示のための項目（画像やプロフィールのURL、絵文字のURL、メンションのURL）は、空・null・不正ならnilにする。`mentions`・`tags`・`emojis`・`media_attachments`がなければ空にする。1ページの全部が読めなくても続きを読めるよう、続きは読めなかった要素のIDでたどる。`Link`ヘッダーは、IDも読めない要素だけのページでしか要らないため使っていない
- [ ] エラーを種類に分けて見せる: 通信なし・タイムアウト、5xxやHTMLの応答、429、401、404・未実装、デコードの失敗に分け、種類ごとの文言にステータスコードを小さく添える。HTMLの本文や`DecodingError`の文は画面に出さない。アラートは使う人の操作の失敗だけにする
- [ ] ストリーミングがつながらないサーバーに備える: v2の`instance`が読めなければv1の`urls.streaming_api`を使い、それでもつながらなければポーリングにする。接続先はセッション中は覚えておく。切れている状態が続いたら控えめに表示する。間隔と表示までの時間は`TuningCatalog`に置く
- [ ] レート制限と通信の回復: 自動で送り直すのはGETと`Idempotency-Key`付きの投稿だけにする。429と503では`Retry-After`・`X-RateLimit-Reset`まで自動の通信を止める。`NWPathMonitor`で電波が戻ったら、読み込みとストリーミングをすぐやり直す
- [ ] 使えない機能をセッションの間だけ止める: 404などで使えないと分かった機能（既読位置の保存など）は、そのセッションの間だけ止める
- [ ] 診断の記録と「接続の状態」画面: API（IDは伏せる）、ステータスコード、エラーの種類、デコードに失敗した`codingPath`と値の形（中身は残さない）、サーバーのソフトウェアと版をinfo以上で残す。リリース版の記録だけで原因を絞れるようにし、デバッグ版は応答の本文を足すだけにする。設定に、サーバーの版、ストリーミングの状態、止めている機能、レート制限、最近のエラーと外した投稿の件数を見る画面を置く
- [ ] 壊れた応答のfixture: 空のURL、項目が欠けた投稿、502のHTML、429、`limit`を丸めるサーバーなどを再現し、上の挙動をテストで押さえる

## M5: 毎日使って見つけた改善

M4までで足りない機能や違和感を、使いながら1つずつ足す。設計に関わる大きな機能は予定せず、これまでに足した、説明にならない代替テキストを隠す設定や、一覧のサムネイルを元の画質で表示する設定のような、設定や表示の細かい改善が中心になる。項目は見つけた時点でここに追加する。

- [ ] トランジションとAPIリクエストの点検: 画面遷移ごとにアニメーションの途中の操作で破綻しないか、タイムラインの更新で不要なリクエストを送っていないかを確かめる
- [ ] プロフィールのアイコンとヘッダー画像をタップして、ビューアで大きく見る: ビューアは開閉の起点にサムネイルのビュー（MediaTileView）を使うため、アイコンとヘッダー画像からも起点を渡せるようにする
- [ ] 本文のメンションをタップして、プロフィールを開く: 本文のリンクがまだタップできないため、リンクのタップと一緒に入れる。開く相手のIDは`status.mentions`から引ける
- [ ] フォローしたあとに、フォロワー数を読み直す: フォローのAPIは関係だけを返すため、いまはプロフィールを開き直すまで数が古いまま
- [x] タブバーの上に常に置く投稿欄: 1、2行の短い投稿や返信を、タイムラインを見たまま書けるようにする。書いていないときは細いカプセルにして閲覧を邪魔せず、書くときは同じバーがキーボードの上へ上がる
- [ ] 投稿欄の下書きを、アプリを起動し直しても残す: いまはメモリにだけ持っている
- [ ] 投稿欄で注意書き（CW）を書く: いまは全画面の投稿画面に広げたときだけ書ける
- [ ] Mac（Designed for iPad）で、投稿やチューニングのシートが出始めるまで遅いのを直す: 押してから何も出ずにもたつき、そのあとパッと出る。iPhoneでは起きない。AeroSpaceを終了しても、Releaseビルドでも変わらなかった。Time Profilerでは、シートを出す直前のSwiftUIの最初のレイアウト（`UISheetPresentationController _transitionWillBegin` → `_UIHostingView.layoutSubviews`）に120〜190msかかっていたが、それだけで説明できるかは分かっていない。次はInstrumentsのAnimation HitchesやSwiftUIのテンプレートで、押してから出始めるまでを測る
