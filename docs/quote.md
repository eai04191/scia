# 引用

投稿の中の引用をどう見せるかと、引用してどう投稿するかで、作者が決めたこと。APIの形と推奨はMastodonの[Implementing quote posts](https://docs.joinmastodon.org/client/quotes/)、[Quote](https://docs.joinmastodon.org/entities/Quote/)、[QuoteApproval](https://docs.joinmastodon.org/entities/QuoteApproval/)にある。

## 形

- 本文の下に、角の丸いカードを1つ置く。中身は小さいアイコンと名前とハンドルの行、本文、添付ファイルの順に並べる
- カードはXの投稿のカードと同じ部品で作る
- 引用元の本文は外側の本文と同じく、長ければ切って「続きを読む」を出す（[long-post.md](long-post.md)）
- 引用元の添付ファイルはタイムラインと同じ部品で並べ、同じビューアで開く
- 引用元のリンクカードは出さない。引用元の投票は選択肢を並べず、「投票」の1行のラベルだけを出す。カードの中が投稿1件分に近い重さになるのを避けるため
- 引用のある投稿にはリンクカードを付けない（[link-card.md](link-card.md)）
- 引用のある投稿では`state`によらず、本文の`quote-inline`の要素（サーバーが互換のために足す`RE: <リンク>`）を消す。引用のない投稿では消さない

## 選択したとき

- カードの選択は引用元の投稿のスレッドを開く
- カードの中のアイコンはプロフィールを、添付ファイルはビューアを、本文のリンクはリンクを開く。行の中のほかの部品と同じく、カードの選択より先に受ける

## 引用元を出せないとき

引用元を出せない`state`では、カードと同じ枠に、文言を1行だけ出す。知らない`state`は`unauthorized`として扱う。

| state | 出す内容 |
|---|---|
| `pending` | 承認待ちの引用であること |
| `rejected`、`revoked` | 引用元の投稿者が引用を取り消したこと |
| `deleted` | 引用元の投稿が削除されたこと |
| `unauthorized` | 引用元の投稿を表示できないこと |
| `blocked_account`、`blocked_domain`、`muted_account` | ブロックまたはミュートしている人の投稿であること。選択すると、カードを開いて中身を出す |

## 閲覧注意とフィルター

- 引用元に注意書き（CW）があれば、カードの中で折りたたむ。外側の投稿の注意書きを開くまでは、カードごと隠す
- 引用元の添付ファイルのぼかしは、添付ファイルと同じく投稿ごとに保持する
- 引用元にも外側の投稿と同じ文脈のフィルターを当てる。「警告」に一致したら、カードの中で折りたたむ。「隠す」に一致したら、外側の投稿は出したまま、カードを「フィルターで隠した」ことを示す1行にする

## 入れ子

- カードは1段だけにする。引用元がさらに投稿を引用していたら、カードの末尾に、引用した投稿があることを示す1行を出す
- 入れ子の引用はIDだけの`ShallowQuote`で届く。`quoted_status_id`が入るのは、`accepted`とブロック・ミュートの3つの`state`だけなので、そのときだけ1行を選択できるようにし、選択するとその投稿のスレッドを開く。ほかの`state`では選択できる見た目にせず、「引用元を出せないとき」と同じ文言を出す

## 承認があとから届くこと

Mastodonはほかのサーバーの投稿の引用の承認を確かめられなかったとき、承認待ちのまま配信し、あとで確かめ直す。確かめ終えたことはストリーミングで流すが、届くのはその投稿の作者のフォロワーのホームだけで、引用元の中の引用は引用元の作者のフォロワーにしか届かない。ストリーミングが切れている間に流れたものも届かない。

- 引用か、引用元の中の引用が承認待ちの投稿は、リンクカードと同じ予定でサーバーから取り直し、承認されたらカードに反映する（[link-card.md](link-card.md)の「カードが後から届くこと」）
- 取り直すのはカードを出している行だけにする。お気に入りやブーストの通知で、カードの代わりにラベルだけを出す行は取り直さない

## 通知とブースト

- 「引用」の通知とメンションでは、投稿と同じくカードを出す
- お気に入りやブーストの通知で投稿を再掲するときは、カードを出さず、引用のある投稿であることを示す1行のラベルだけを出す
- 引用のある投稿のブーストではふつうの投稿と同じくカードを出す

## 受け取ったあとの変化

- 引用元の編集と削除がストリーミングで届いたら、その引用元を出しているカードにも反映する。編集は新しい中身に替え、削除は「引用元を出せないとき」の削除の1行にする。自分で編集や削除をしたときも同じ
- 読み込んだあとで引用元の人をミュートかブロックしたら、その人の引用元を、届いたときからミュートかブロックしていたのと同じく、選択して開くまで隠す。解除したら、隠すのをやめる
- カードの高さが変わるときは、[vision.md](vision.md)の「タイムラインの動き」の、見えている行の高さが変わるときと同じく、下の行ごと動かしてつなぐ
- `pending`から`accepted`への変化はストリーミングで流れないため、投稿を再読み込みしたときに反映する

## 引用して投稿する

- 投稿のメニューの「引用」で、投稿欄で引用して書き始める。ブーストなら元の投稿を引用する。既定では反応のつづきのグループ（編集、ブックマーク）に置く。返信・お気に入り・ブーストの横並びは3個までなので、そこには入れない
- 引用できるかは投稿の`quote_approval.current_user`で決める
  - `automatic`: 選択できる
  - `manual`: 選択できる。投稿者が認めるまで引用が表示されないことを、項目のサブタイトルに出す
  - `denied`、`unknown`、知らない値: 無効にして出し、理由をサブタイトルに出す。`automatic`か`manual`に`followers`があれば、フォロワーだけが引用できること、なければ引用できない投稿であることを書く。ドキュメントは`unknown`を`denied`として扱うよう勧めている
  - `quote_approval`がない（引用に対応していないサーバー）: 項目を出さない。選択できるかを決められないため
  - 公開とハッシュタグのストリーミングで届いた投稿: サーバーがログインしていない人向けの形で配り、`current_user`がいつも`denied`になるので、選択できる形で出す。選択したら投稿を再読み込みし、引用できれば始め、できなければアラートで理由を伝える
- 投稿欄では返信と同じラベルの行に、引用元の投稿者を書いたラベルを×付きで出す。ラベルを選択すると、返信と同じくタイムラインの引用元を表示する。引用元の中身のカードは投稿欄に出さない。欄が大きくなり、見ているタイムラインを隠すため
- 返信と引用は一緒に付けない。引用を選ぶと返信先を外し、返信を選ぶと引用を外す。どちらも返信を付け替えるときと同じく、自分で書いた本文を残し、返信先から自動で入れた宛先だけを外す。ラベルの行を2行にしないため
- 書いていないときのカプセルには、返信と同じく、引用のラベルのアイコンだけを出す
- 編集している途中に引用を選んだら、返信と同じく、編集をやめてよいか聞いてから引用を始める
- Mastodonは引用に添付ファイルと投票を付けられないので、引用している間は、添付と投票の項目を無効にする。添付ファイルか投票の付いた下書きで引用を選んだら、外してよいか聞き、外すなら外して引用を付ける。本文は残す
- 本文が空でも、引用だけで送れる。Mastodonは引用のある投稿に本文を求めないため
- 公開範囲は返信と同じく、引用元と既定のうち届く範囲が狭い方で始める。引用元がフォロワー限定なら、フォロワー限定より広い範囲を選べなくする。サーバーがフォロワー限定の投稿の引用を、フォロワー限定でしか受け付けないため。メンションした相手のみにするときは、引用元の投稿者を本文でメンションしないとサーバーが断るが、サーバーの文言で知らせるに任せる
- 引用した投稿を誰が引用できるかは、ほかの投稿と同じく「引用できる人を決める」に従う

## 引用できる人を決める

自分の投稿を誰が引用できるかを、投稿ごとに決める。APIは[statuses](https://docs.joinmastodon.org/methods/statuses/)の`quote_approval_policy`と`interaction_policy`にある。

- 選べるのは、Mastodonが受け付ける3つ。「誰でも」（`public`）、「フォロワーのみ」（`followers`）、「自分のみ」（`nobody`）
- 書き始めたときは、アカウントの既定（`posting:default:quote_policy`）にする。既定はアカウントの画面の「投稿のデフォルト」で変える（[account-screen.md](account-screen.md)）
- 引用に対応していないサーバー（既定が返らない）では、選ぶ項目を出さず、送らない

### 投稿欄で選ぶ

- 公開範囲のメニューの中に、公開範囲の選択肢の下に区切って並べる。公式のWebクライアントが、公開範囲と同じ場所で選ばせているため。＋の中に公開範囲を入れているときのサブメニューにも並べる
- 公開範囲と引用できる人はメニューを閉じずに続けて選べる
- 公開範囲がフォロワーのみかメンションした相手のみの間は、「自分のみ」を選んだ形で見せ、選べなくし、選べないことをセクションの見出しに添える。項目のサブタイトルには書かない。開いたままのメニューで行の高さが変わると、メニューが伸びて下が投稿欄に隠れるため。Mastodonがその公開範囲の投稿をいつも「自分のみ」にするため。選んでいた値は保持しておき、公開範囲を戻したら戻す
- 既定と違う値を選んでいる間は、公開範囲のボタンに引用符のバッジを付ける。バッジは言語のバッジと同じく、送信ボタンと同じ決まりの色で描く（ティントカラーの地に白、モノトーンでは淡い地に本文の色）。公開範囲を＋の中に入れていれば、＋のボタンの右下に付ける。右上は言語のバッジが使うため。前の投稿で選んだ値のまま気づかずに送らないようにするため。公開範囲で「自分のみ」に決まっている間は、自分で選んだものではないので付けない
- 投稿したら、言語と同じく、次の投稿は既定に戻す
- 編集、削除して書き直す、予約の書き直しでは、元の投稿の値を戻し、選び直せる。編集では変えた値を編集と一緒に送る。値を送っていない予約は既定にする
- 投稿の値は公式のWebクライアントと同じく、`quote_approval.automatic`の先頭から読む。3つのどれでもなければ「自分のみ」にする

### 投稿したあとに変える

- 自分の投稿のメニューの「引用できる人」のサブメニューで変える。今の値にチェックマークを付け、項目のサブタイトルにも出す。既定では「その他」に置く
- 公開範囲がフォロワーのみかメンションした相手のみの投稿では、無効にして出し、理由をサブタイトルに出す
- 引用に対応していないサーバーの投稿（`quote_approval`がない）と、ほかの人の投稿では出さない
- 変えても、すでにされた引用は取り消されない。取り消すのは「引用を取り消す」で行う

## 引用した投稿のタイムライン

ある投稿を引用した投稿を並べる。APIは`GET /api/v1/statuses/:id/quotes`。

- 投稿のメニューの「引用した投稿」で開く。誰の投稿でも開ける。「お気に入りした人」と同じく、件数（`quotes_count`）をサブタイトルに出し、0なら出さない。既定では「お気に入りした人」「ブーストした人」の並びに置く
- アクションバーのブーストのボタンの長押しのメニューにも並べる（[post-action-bar.md](post-action-bar.md)）
- 並びは、サーバーが返すとおりにする。続きは応答の`Link`ヘッダーの`next`から読む
- 流れてくるストリームがないので、購読しない。開いたときと、開いたままアプリに戻ったとき、pull to refreshしたときに、最新の1ページを読んで先頭に足す
- 開いた画面は選んでいるタブにプッシュする。タブには置けない
- サーバーのフィルターはスレッドと同じ文脈（`thread`）で当てる。1つの投稿への反応を並べる画面だから。公式のWebクライアントはこの画面でフィルターを当てていないが、投稿のリストに画面の名前を渡していない結果で、当てないための処理があるわけではないので、合わせない
- 既読位置は保存しない

## 引用を取り消す

自分の投稿への引用を、あとから取り消す。APIは`POST /api/v1/statuses/:id/quotes/:quoting_status_id/revoke`。Mastodonは引用を自動で認めるので、断れるのは引用されたあとだけ。

- 自分の投稿を引用していて、引用が認められている（`accepted`）投稿のメニューに「引用を取り消す」を出す。引用した投稿のタイムライン、「引用」の通知、ホームなど、その投稿を出しているどこでも同じ。場所ごとに出す条件を持たない
- 取り消すと戻せないので、確かめてから送る
- 取り消したら、その投稿のカードを「引用元を出せないとき」の取り消しの1行にする。引用した投稿のタイムラインでは、使う人の操作なので、閉じる動きで行を消す
- 既定では削除と同じ並びに置く

## Fedibirdの形

Fedibirdの引用はMastodonの引用より前からあり、APIの形が違う。`instance`の`feature_quote`がtrueのサーバーを、Fedibirdの形として扱う。形はfedibird/mastodonの`app/serializers/rest/status_serializer.rb`、`app/controllers/api/v1/statuses_controller.rb`、`app/models/status.rb`にある。

サーバーで違う決まり（引用できるか、送り方、取り消せるか）は`QuoteRules`に集め、使う側はサーバーの種類を見ずにそこに聞く。届いた投稿はサーバーを見ずに形で読み分ける。

### 読む

- 投稿の`quote`には、`state`がなく、引用元の投稿そのものが入る。認められた引用（`accepted`）として読み、カードで出す
- 引用元の`quote_muted`がtrueなら、ミュートしている人の引用元として、選択して開くまで隠す。Fedibirdはミュート、ブロック、ブロックされている、ドメインのブロックを、この1つの真偽値にまとめて返す
- 引用元の`quote`はいつもnullで、引用元がさらに引用していれば`quote_id`だけが入る。入れ子の1行はこのIDで選択できるようにする
- 本文の末尾の`<span class="quote-inline">`（Fedibirdの投稿は`QT: <リンク>`、Misskeyから来た投稿は`RE: <リンク>`）を、Mastodonの段落と同じく、引用のある投稿でだけ消す
- Fedibirdは引用を参照としても記録し、参照のある投稿の本文の末尾に、参照のページへのリンク（`<span class="reference-link-inline">`の`[参照]`）を足す。参照が引用元の1件だけ（`status_reference_ids`が引用元のIDだけ）の投稿では、このリンクを消す。カードと同じ投稿を二重に示すため。ほかの参照もある投稿ではSciaに参照を出す画面がないので残す
- 引用元が削除されると、Fedibirdは`quote_id`を消すので、引用のない投稿として届く。削除の1行は出ない

### 引用して投稿する

- 「引用」は公開か未収載の投稿では選択できる形で、ほかの公開範囲では無効にして理由を添えて出す。Fedibirdは、引用元が公開か未収載のときだけ引用を受け付けるため
- 引用元のIDは`quote_id`で送る。`quoted_status_id`で送ると、Fedibirdは引用のない投稿として受け付ける。サーバーの形は、セッションが読めた値を使い、まだ読めていなければ送る前に読む。読めなければ送らずに失敗させる
- 引用している間は、Mastodonと同じく、添付と投票を無効にし、返信と一緒に付けない。Fedibirdはどれも受け付けるが、投稿欄の決まりをサーバーで分けない
- 本文が空の引用も、Mastodonと同じく送れる形にする。Fedibirdは添付のない投稿に本文を求めるので断るが、投稿欄では止めず、サーバーの文言で知らせるに任せる

### ないもの

- 承認、引用できる人、引用の取り消しはない。「引用できる人」と「引用を取り消す」は出さない
- 引用した投稿のタイムラインは出さない。`quotes_count`が届かず、`GET /api/v1/statuses/:id/referred_by`は引用でない参照も混ぜて返すため
- 「引用」の通知は届かない。Fedibirdは引用を参照の通知（`status_reference`）で知らせる
