# 引用

投稿の中の引用をどう見せるかと、引用してどう投稿するかで、作者が決めたこと。APIの形と推奨は、Mastodonの[Implementing quote posts](https://docs.joinmastodon.org/client/quotes/)、[Quote](https://docs.joinmastodon.org/entities/Quote/)、[QuoteApproval](https://docs.joinmastodon.org/entities/QuoteApproval/)にある。

## 形

- 本文の下に、角の丸い囲みを1つ置く。中身は、小さいアイコンと名前とハンドルの行、本文、添付ファイルの順に並べる
- 囲みは、Xの投稿の囲みと同じ部品で作る
- 引用元の本文は、外側の本文と同じく、長ければ切って「続きを読む」を出す（[long-post.md](long-post.md)）
- 引用元の添付ファイルは、タイムラインと同じ部品で並べ、同じビューアで開く
- 引用元のリンクカードは出さない。引用元の投票は、選択肢を並べず、「投票」の1行のラベルだけを出す。囲みの中が投稿1件分に近い重さになるのを避けるため
- 引用のある投稿には、リンクカードを付けない（[link-card.md](link-card.md)）
- 引用のある投稿では、`state`によらず、本文の`quote-inline`の要素（サーバーが互換のために足す`RE: <リンク>`）を消す。引用のない投稿では消さない

## 押したとき

- 囲みの押下は、引用元の投稿のスレッドを開く
- 囲みの中のアイコンはプロフィールを、添付ファイルはビューアを、本文のリンクはリンクを開く。行の中のほかの部品と同じく、囲みの押下より先に受ける

## 引用元を出せないとき

引用元を出せない`state`では、囲みと同じ枠に、文言を1行だけ出す。知らない`state`は`unauthorized`として扱う。

| state | 出す内容 |
|---|---|
| `pending` | 承認待ちの引用であること |
| `rejected`、`revoked` | 引用元の投稿者が引用を取り消したこと |
| `deleted` | 引用元の投稿が削除されたこと |
| `unauthorized` | 引用元の投稿を表示できないこと |
| `blocked_account`、`blocked_domain`、`muted_account` | ブロックまたはミュートしている人の投稿であること。押すと、囲みを開いて中身を出す |

## 閲覧注意とフィルター

- 引用元に注意書き（CW）があれば、囲みの中で折りたたむ。外側の投稿の注意書きを開くまでは、囲みごと隠す
- 引用元の添付ファイルのぼかしは、添付ファイルと同じく投稿ごとに覚える
- 引用元にも、外側の投稿と同じ文脈のフィルターを当てる。「警告」に一致したら、囲みの中で折りたたむ。「隠す」に一致したら、外側の投稿は出したまま、囲みを「フィルターで隠した」ことを示す1行にする

## 入れ子

- 囲みは1段だけにする。引用元がさらに投稿を引用していたら、囲みの末尾に、引用した投稿があることを示す1行を出す
- 入れ子の引用は、IDだけの`ShallowQuote`で届く。`quoted_status_id`が入るのは、`accepted`とブロック・ミュートの3つの`state`だけなので、そのときだけ1行を押せるようにし、押すとその投稿のスレッドを開く。ほかの`state`では押せる見た目にせず、「引用元を出せないとき」と同じ文言を出す

## 承認があとから届くこと

Mastodonは、ほかのサーバーの投稿の引用の承認を確かめられなかったとき、承認待ちのまま配信し、あとで確かめ直す。確かめ終えたことはストリーミングで流すが、届くのはその投稿の作者のフォロワーのホームだけで、引用元の中の引用は引用元の作者のフォロワーにしか届かない。ストリーミングが切れている間に流れたものも届かない。

- 引用か、引用元の中の引用が承認待ちの投稿は、リンクカードと同じ予定でサーバーから取り直し、承認されたら囲みに反映する（[link-card.md](link-card.md)の「カードが後から届くこと」）
- 取り直すのは、囲みを出している行だけにする。お気に入りやブーストの通知で、囲みの代わりにラベルだけを出す行は取り直さない

## 通知とブースト

- 「引用」の通知とメンションでは、投稿と同じく囲みを出す
- お気に入りやブーストの通知で投稿を再掲するときは、囲みを出さず、引用のある投稿であることを示す1行のラベルだけを出す
- 引用のある投稿のブーストでは、ふつうの投稿と同じく囲みを出す

## 受け取ったあとの変化

- 引用元の編集と削除がストリーミングで届いたら、その引用元を出している囲みにも反映する。編集は新しい中身に替え、削除は「引用元を出せないとき」の削除の1行にする。自分で編集や削除をしたときも同じ
- 読み込んだあとで引用元の人をミュートかブロックしたら、その人の引用元を、届いたときからミュートかブロックしていたのと同じく、押して開くまで隠す。解除したら、隠すのをやめる
- 囲みの高さが変わるときは、[vision.md](vision.md)の「タイムラインの動き」の、見えている行の高さが変わるときと同じく、下の行ごと動かしてつなぐ
- `pending`から`accepted`への変化はストリーミングで流れないため、投稿を読み直したときに反映する

## 引用して投稿する

- 投稿のメニューの「引用」で、投稿欄で引用して書き始める。ブーストなら元の投稿を引用する。既定では、反応のつづきのまとまり（編集、ブックマーク）に置く。返信・お気に入り・ブーストの横並びは3個までなので、そこには入れない
- 引用できるかは、投稿の`quote_approval.current_user`で決める
  - `automatic`: 押せる
  - `manual`: 押せる。投稿者が認めるまで引用が表示されないことを、項目のサブタイトルに出す
  - `denied`、`unknown`、知らない値: 押せない形で出し、理由をサブタイトルに出す。`automatic`か`manual`に`followers`があれば、フォロワーだけが引用できること、なければ引用できない投稿であることを書く。ドキュメントは`unknown`を`denied`として扱うよう勧めている
  - `quote_approval`がない（引用に対応していないサーバー）: 項目を出さない。押せるかを決められないため
  - 公開とハッシュタグのストリーミングで届いた投稿: サーバーがログインしていない人向けの形で配り、`current_user`がいつも`denied`になるので、押せる形で出す。押したら投稿を読み直し、引用できれば始め、できなければアラートで理由を伝える
- 投稿欄では、返信と同じラベルの行に、引用元の投稿者を書いたラベルを×付きで出す。ラベルを押すと、返信と同じくタイムラインの引用元を表示する。引用元の中身の囲みは投稿欄に出さない。欄が大きくなり、見ているタイムラインを隠すため
- 返信と引用は一緒に付けない。引用を選ぶと返信先を外し、返信を選ぶと引用を外す。どちらも、返信を付け替えるときと同じく、自分で書いた本文を残し、返信先から自動で入れた宛先だけを外す。ラベルの行を2行にしないため
- 書いていないときのカプセルには、返信と同じく、引用のラベルのアイコンだけを出す
- 編集している途中に引用を選んだら、返信と同じく、編集をやめてよいか聞いてから引用を始める
- Mastodonは引用に添付ファイルと投票を付けられないので、引用している間は、添付と投票の項目を押せなくする。添付ファイルか投票の付いた下書きで引用を選んだら、外してよいか聞き、外すなら外して引用を付ける。本文は残す
- 本文が空でも、引用だけで送れる。Mastodonは引用のある投稿に本文を求めないため
- 公開範囲は、返信と同じく、引用元と既定のうち届く範囲が狭い方で始める。引用元がフォロワー限定なら、フォロワー限定より広い範囲を選べなくする。サーバーがフォロワー限定の投稿の引用を、フォロワー限定でしか受け付けないため。メンションした相手のみにするときは、引用元の投稿者を本文でメンションしないとサーバーが断るが、サーバーの文言で知らせるに任せる
- 引用した投稿を誰が引用できるかは、ほかの投稿と同じく「引用できる人を決める」に従う

## 引用できる人を決める

自分の投稿を誰が引用できるかを、投稿ごとに決める。APIは[statuses](https://docs.joinmastodon.org/methods/statuses/)の`quote_approval_policy`と`interaction_policy`にある。

- 選べるのは、Mastodonが受け付ける3つ。「誰でも」（`public`）、「フォロワーのみ」（`followers`）、「自分のみ」（`nobody`）
- 書き始めたときは、アカウントの既定（`posting:default:quote_policy`）にする。既定は、アカウントの画面の「投稿の既定」で変える（[account-screen.md](account-screen.md)）
- 引用に対応していないサーバー（既定が返らない）では、選ぶ項目を出さず、送らない

### 投稿欄で選ぶ

- 公開範囲のメニューの中に、公開範囲の選択肢の下に区切って並べる。公式のWebクライアントが、公開範囲と同じ場所で選ばせているため。＋の中に公開範囲を入れているときのサブメニューにも並べる
- 公開範囲と引用できる人は、メニューを閉じずに続けて選べる
- 公開範囲がフォロワーのみかメンションした相手のみの間は、「自分のみ」を選んだ形で見せ、選べなくし、理由を添える。Mastodonがその公開範囲の投稿をいつも「自分のみ」にするため。選んでいた値は覚えておき、公開範囲を戻したら戻す
- 既定と違う値を選んでいる間は、公開範囲のボタンに引用符のバッジを付ける。公開範囲を＋の中に入れていれば、＋のボタンに付ける。前の投稿で選んだ値のまま気づかずに送らないようにするため。公開範囲で「自分のみ」に決まっている間は、自分で選んだものではないので付けない
- 投稿したら、言語と同じく、次の投稿は既定に戻す
- 編集、削除して書き直す、予約の書き直しでは、元の投稿の値を戻し、選び直せる。編集では、変えた値を編集と一緒に送る。値を送っていない予約は、既定にする
- 投稿の値は、公式のWebクライアントと同じく、`quote_approval.automatic`の先頭から読む。3つのどれでもなければ「自分のみ」にする

### 投稿したあとに変える

- 自分の投稿のメニューの「引用できる人」のサブメニューで変える。今の値にチェックマークを付け、項目のサブタイトルにも出す。既定では「その他」に置く
- 公開範囲がフォロワーのみかメンションした相手のみの投稿では、押せない形で出し、理由をサブタイトルに出す
- 引用に対応していないサーバーの投稿（`quote_approval`がない）と、ほかの人の投稿では出さない
- 変えても、すでにされた引用は取り消されない。取り消すのは「引用を取り消す」で行う

## 引用した投稿のタイムライン

ある投稿を引用した投稿を並べる。APIは`GET /api/v1/statuses/:id/quotes`。

- 投稿のメニューの「引用した投稿」で開く。誰の投稿でも開ける。「お気に入りした人」と同じく、件数（`quotes_count`）をサブタイトルに出し、0なら出さない。既定では「お気に入りした人」「ブーストした人」の並びに置く
- アクションバーのブーストのボタンの長押しのメニューにも並べる（[post-action-bar.md](post-action-bar.md)）
- 並びは、サーバーが返すとおりにする。続きは、応答の`Link`ヘッダーの`next`から読む
- 流れてくるストリームがないので、購読しない。開いたときと、開いたままアプリに戻ったとき、引っぱったときに、最新の1ページを読んで先頭に足す
- 開いた画面は、選んでいるタブに積む。タブには置けない
- サーバーのフィルターは、スレッドと同じ文脈（`thread`）で当てる。1つの投稿への反応を並べる画面だから
- 既読位置は保存しない

## 引用を取り消す

自分の投稿への引用を、あとから取り消す。APIは`POST /api/v1/statuses/:id/quotes/:quoting_status_id/revoke`。Mastodonは引用を自動で認めるので、断れるのは引用されたあとだけ。

- 自分の投稿を引用していて、引用が認められている（`accepted`）投稿のメニューに「引用を取り消す」を出す。引用した投稿のタイムライン、「引用」の通知、ホームなど、その投稿を出しているどこでも同じ。場所ごとに出す条件を持たない
- 取り消すと戻せないので、確かめてから送る
- 取り消したら、その投稿の囲みを「引用元を出せないとき」の取り消しの1行にする。引用した投稿のタイムラインでは、使う人の操作なので、閉じる動きで行を消す
- 既定では、削除と同じ並びに置く
