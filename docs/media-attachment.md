# メディアの添付

投稿にメディアを添付するときの、選び方の仕様と実装の決め事。検証用の小さなアプリを作り、シミュレーターと実機で比べて決めた。

## 選び方

システムの写真ピッカー（`PHPickerViewController`）を、シートとして直接出す。別プロセスで動くので、写真ライブラリへのアクセス許可は要らない。

シートの高さは2段だけで、途中では止まらない。

- 低い: キーボードと同じ高さ。タブや検索などの部品を出さず、写真のグリッドだけを見せる。後ろは暗くしない
- 最大: 写真／コレクションのタブ、検索、✓を出す

操作は次のとおり。

- 低い状態で写真の上を上へ払うと、最大に広がって部品が出る。下げると部品が消える
- 下へ払うか、最大で✓を押すと閉じる。閉じることが決まった時点で、キーボードが上がってくる
- 選んだ写真はその場で受け取る。枚数の上限は接続先のサーバーに合わせる
- シートを出している間も、投稿欄は書いている形のまま、低いシートのすぐ上に留まる。投稿欄のメディアのボタンをもう一度押すか、入力欄に触れると、シートを閉じてキーボードに戻る
- 前に選んだものがある状態で開き直すと、ピッカーは前に選んだ写真の位置で開く

## 実装の決め事

- 選択は`selection = .continuousAndOrdered`で受け取る。`selectionLimit`は、`/api/v2/instance`の`configuration.statuses.max_media_attachments`（Mastodon 4.0から）にする。項目がないサーバーでは、Mastodonの既定値の4にする
- シートの`detents`は低い（独自の高さ）と`.large()`の2つにする。`largestUndimmedDetentIdentifier`は低いほう、`prefersScrollingExpandsWhenScrolledToEdge`は`true`にする
- 部品の出し入れは、余白の設定`edgesWithoutContentMargins`で行う。低いときは`.all`、最大のときは`[]`にすると、バーが消えたり出たりする。`sheetPresentationControllerDidChangeSelectedDetentIdentifier`で高さの変化を受け取り、`updatePicker(using:)`で切り替える。`disabledCapabilities`はピッカーを作った後に変えられないので使わない
- キーボードは、`presentationControllerWillDismiss`で`transitionCoordinator.notifyWhenInteractionChanges`を待ち、閉じることが決まった時点（キャンセルされていないとき）で出す。`presentationControllerDidDismiss`まで待つと、シートが閉じ終わってから一拍遅れて出る
- 低いシートの高さは`TuningCatalog`の項目にする。キーボードの高さに合わせるか、固定の値にするかを選べるようにする。キーボードの高さは日本語入力の候補の段や他社のキーボードで変わり、ハードウェアキーボードでは0になるので、一度もキーボードを出していないときも含めて固定の値が要る
- 高さが変わるたびに、`scrollToInitialPosition()`でグリッドを最初の位置（最新の写真の位置）に戻す。余白を変えてもピッカーはグリッドの位置を合わせ直さず、広げると最新の段が見出しの裏に潜り、広げて低くした後は写真の上を払ってもシートが広がらずにグリッドがスクロールする。前に選んだものがある状態で開いたときは戻さない。戻す先は開いた位置ではなく一番上なので、前に選んだ写真を見失わせてしまう
- 投稿欄は、シートを出す前にバーの下端を「画面の下端からシートの高さ＋余白」に留める制約を付けてからキーボードを閉じ、`textViewDidEndEditing`でも書いている状態を解かない。閉じてキーボードが上がりきった`keyboardDidShowNotification`で制約を外す。キーボードの表示の知らせが来なくても、シートを閉じた後に書き終えれば制約を外す
- シートの高さは、最後に出したキーボードの画面の下端からの高さ（100pt以下はハードウェアキーボードとみなして覚えない）から、下の安全領域を引いて決める
- シートを出したまま投稿したら、シートを閉じて書き終える。投稿の失敗はシートを出している間は出せないので、閉じ終わってから出す
- 選んだメディアのサムネイルは、メディアのIDごとに覚えておき、選んだり外したりした分だけ足し引きする。表示する大きさで読み込み（`loadFileRepresentation`と`CGImageSourceCreateThumbnailAtIndex`）、動画は`AVAssetImageGenerator`で1コマ取り出す。`loadObject(ofClass: UIImage.self)`で元の大きさのまま読むと、大きな写真ではグレーの時間が長く、動画は表示できない

## 公式に保証されていない挙動への依存

ピッカーをシートとして直接出す使い方は、「選んで✓（追加）かキャンセルで閉じる」前提で作られている。選んだメディアをその場で受け取る`continuous`は、ピッカーを自分の画面に埋め込む前提の設定である。この組み合わせで理想の動きを出すため、次の2つは観察した挙動に頼っている。

- 閉じられなくなるフラグ: 1枚でも選ぶと、ピッカーが自分の`isModalInPresentation`を`true`にし、払っても閉じられなくなる。`presentationControllerDidAttemptToDismiss`も呼ばれない。選択はその場で受け取っていて閉じても失われないので、選択が届くたびに`false`に戻す
- ✓の見分け方: `continuous`では、✓を押すと今の選択と同じ内容がもう一度届く。選択が変わらずに届いたら✓とみなして閉じる
- グリッドを戻す時点: 余白の変更（`updatePicker(using:)`）と同じ処理の中で`scrollToInitialPosition()`を呼ぶと、変更前の余白で戻ってしまい、最新の段が潜ったままになる。`DispatchQueue.main.async`で次の順番に回すと、実機でも効いた。決まった時間を待つ必要はなかった

検証の途中で一度だけ、フラグを戻したのに閉じられなかった回があった。原因は分かっておらず、その後は再現していない。どちらかが効かなくなったときに備えて、次の逃げ道を用意する。

- 払って閉じられなくなっても、プログラムからの`dismiss`は効く。低いシートの上に見えている投稿欄のボタンから、シートを閉じられるようにする
- ✓の見分けが効かなくなっても、払えば閉じられる
- どちらの回避策も、発動したことを`SciaLog`にinfoで出し、違和感レポートで追えるようにする

次のことは、確かめたうえで直せないと判断した。

- 写真をタップして選んだ直後に払うと、シートが広がらずにグリッドがスクロールする。少し待ってから払えば広がる。閉じられなくなるフラグのせいではない（フラグを立てたままでも、待てば広がった）。ピッカーは、フラグを選択の知らせより前に、監視（KVO）に通知されない方法で立てている。タップ直後の指の動きはピッカー側が受け取っているとみられ、アプリ側から変える手はない。ピッカーは継承をサポートしないと明記されているので、継承してフラグを止める手も採らない
- シートを出す切り替えの間（起動直後の初回は数秒）は、UIKitが画面への操作を受け付けず、その間のタップは消える

## 採らなかった案

- ピッカーをキーボードの代わりに出す（`inputViewController`に埋め込む）: キーボードと同じ高さで入れ替えられ、選択もその場で届いた。ただし切り替えは瞬時で動きがなく、セルの大きさや並びは変えられない
- ピッカーを自前の入れ物に入れてシートで出す: 入れ物にはフラグが立たないので選んでも閉じられ、✓も要らない。ただしピッカーは別プロセスで動くため、シートから写真のスクロールが見えず、写真の上を払ってもシートが広がらない。上端に自前のつまみの帯を置かないと広げられない
- 選択を✓を押したときだけ受け取る（`continuous`にしない）: ✓は公式に通知されるが、選んだメディアがその場で反映されない。選択がある間は払って閉じられず、部品を消した低い状態では✓も見えないので、閉じられなくなる
- 上限を無制限にして、枚数の上限をアプリ側で守る: 「4項目まで選択できます。」の表示は消えるが、5枚目を押しても何も起きないように見える
- PhotoKitで独自のグリッドを作る: 見た目は自由にできるが、写真ライブラリへのアクセス許可が要る

## 未決のこと

- エラーの伝え方（未設計）: 枚数、動画やGIFの扱い、サイズの上限を受け付けるかはサーバーが決めるので、投稿ボタンを押した後のエラーとして伝える。選んだ後のアップロード（`POST /api/v2/media`）で起きるエラーも含めて設計する
- 投稿欄との組み合わせで残った違和感（シミュレーターで確かめた）
  - 低いシートの上端がキーボードの上端より5pt低い。iOS 26のシートは画面の下端から浮いていて、その分が高さに入らない。出した後に実際の上端を測って高さを直すのが案
  - 開くとき、キーボードが下がりきってからシートが上がるまで約0.3秒、タイムラインとタブバーが見える。先にシートを出し始めてからキーボードを閉じるのが案
  - 払って閉じるとき、キーボードが上がり始めるまで約0.25秒遅れ、その間はバーとシートの間が空く
  - 閉じる途中に投稿欄のメディアのボタンを押しても、開き直さずに無視している。閉じ終わってから開き直すと、キーボードが上がってまた下がる往復になる
  - 前に選んだものがある状態で開いた回は、グリッドを戻さないので、写真の上を払ってもシートが広がらずにスクロールしやすい。前に選んだものをピッカーに渡さず、選んだものの確認や外す操作を投稿欄のサムネイルで行えば解消できる
- ハードウェアキーボードや日本語入力の候補の段でキーボードの高さが変わるときの、シートの高さと投稿欄の位置（未検証）
- 代替テキストの入力、写真以外の入口（ペースト、カメラ、ファイル）
- iPadと将来のmacOSでの見え方
