# メディアの添付

投稿へのメディアの添付で、作者が決めたこと。実装の細部と、公式に保証されていない挙動に頼っている箇所は、コードのコメントに書く。

## 選び方

- システムの写真ピッカーを、2段のシートで出す。低いときはキーボードと同じ高さで写真だけを並べ、最大のときはタブと検索と✓を出す。途中の高さでは止まらない
- 低いときに写真の上を上へ払うと、最大に広がる。下へ払うか✓を押すと閉じて、キーボードに戻る
- 選んだものは、その場で投稿欄に入る。開き直すと、前に選んだものが選ばれた状態で出る
- 低いときの高さは、チューニングで選ぶ

## 枚数とエラー

- 枚数の上限は、接続先のサーバーの値（`/api/v2/instance`の`max_media_attachments`）に合わせる。項目がなければ4にする
- 受け付けるかどうかはサーバーが決めるので、断られたらエラーとして伝える。伝え方は、エラーの伝え方の設計に合わせる

## 選んだメディアのプレビュー

選んだメディアは、投稿欄でサムネイルの列として見せ、タップするとタイムラインと同じビューアで開く。代替テキストはビューアの代替テキストの表示から入れ、並べ替えは列で行う。

### 見え方と操作

- 投稿欄の入力欄の上に、同じ大きさの正方形のサムネイルを横一列に並べる。上限が4枚より多いサーバーでも1段のまま全部見せ、並べ替えても枠の大きさは変えない
- サムネイルをタップすると、タイムラインと同じビューアがサムネイルから広がって開き、閉じるとサムネイルへ戻る。ピッカーのシートを出している間に叩いたときも、シートの上に開き、閉じるとシートと投稿欄はそのまま残る
- ビューアのメニューは「代替テキストを編集」「削除」にする。失敗したものには「再試行」も出す
- ビューアを開いている間も、投稿欄は書いている形のまま、キーボードの高さに留める
- 閉じたあと、キーボードは閉じる動きが終わってから戻す。それまでの間（シミュレーターで約0.5秒）、投稿欄とタブバーの間が空くのは受け入れる。空く時間が気になるかは実機で確かめる

### 代替テキストの入力

- ビューア下の代替テキストの帯は、空でも「代替テキストを追加」と出す。タップすると複数行の入力欄に変わり、キーボードのすぐ上に付く
- 入力中は、キーボードと入力欄に隠れない範囲に画像を縮めて収め、書きながら画像を見られるようにする
- 書いている間に画像の上を払っても、ビューアは閉じない。まずキーボードを下げて書き終え、もう一度払えば閉じる
- 入力欄の中のドラッグ（スクロール、長押しからのカーソル移動）は、払って閉じる操作とは別に、そのまま入力欄が受ける
- 上限（`description_limit`）に近づいたら、残りの文字数を出す
- アップロードが済む前にも書ける。書いた値は`DraftAttachment.description`に入れておき、アップロードと一緒に送る。済んだ後に書いたら、書き終えた時点で`PUT /api/v1/media/:id`を送る

### 並べ替え

- 列のコレクションビューのドラッグ&ドロップで並べ替え、ドロップの処理で並びを当て直す。iOS 15からは、iPhoneでも既定でドラッグできる（`dragInteractionEnabled`）
- VoiceOverとキーボードのために、セルに「先頭へ移動」「前へ移動」「後ろへ移動」「末尾へ移動」「削除」のカスタムアクションを付け、長押しのメニューにも同じ項目を置く
- ビューアの中では並べ替えない
- ピッカーは自分の順番で選択を送ってくるので、そのまま受け取ると、投稿欄で並べ替えた順が上書きされる。ピッカーからは、足したものと外したものだけを取り込み、並びはアプリ側の順番を保つ

### 添付ごとの状態

サムネイルの列に重ねて出し、ビューアでは上の中央（枚数の表示の近く）に同じ状態を出す。

| 状態 | 見せ方 |
|---|---|
| 送信中（`uploading`） | サムネイルを少し暗くし、円で進み具合を出す |
| 変換待ち（`processing`） | 円を回り続ける表示に替える |
| 済み（`uploaded`） | 何も重ねない。代替テキストがあればタイムラインと同じALTの札 |
| 代替テキストの送信中（`needsDescriptionUpdate`） | ALTの札の位置に小さく回る表示 |
| 失敗（`failed`） | 赤い感嘆符。タップで理由と「再試行」「削除」 |

投稿ボタンを押せるのは、全部が済んだときだけ。失敗の文言と出し方は、エラーの伝え方の設計に合わせる。

### 実装の決め事

- ビューアに「投稿欄から開いたか」の分岐を足さず、次の3つを外から渡す形に分ける。分岐を足していくと、閉じる操作や開閉の動きの条件が絡まるため
  - 描く中身: 種類・縦横比・代替テキスト・画像の出どころ（サーバーのURLか、手元のファイルとサムネイル）を持つ型をページに渡す。手元のファイルのURLで偽の`MediaAttachment`を作らない。IDがサーバーのものと混ざり、`MediaImageStore`が手元のファイルをキャッシュに写し、共有と保存が一時ファイルに効くため
  - 開閉の起点: 列のセルにも`MediaTileView`を置き、手元の画像を受け取れるようにする。閉じる動きは毎フレーム戻り先を探し直すので、投稿欄の位置が動いても追える
  - 操作: メニューの項目と、代替テキストの帯をタップしたときの動きを渡す
- 投稿欄から開くときは、Macで動かしていても`MediaWindow`の別ウィンドウにせず、その場で開く。別のシーンと下書きをつながずに済ませるため
- ビューアは、ピッカーのシートを出していればシートから、出していなければ投稿欄を置いた画面から出す
- 開く前に、入力欄のキーボードを自分で閉じる。開いている間は、`textViewDidEndEditing`で書いている状態を解かない。ビューアは表示されると最初の応答者になる（Escで閉じるため）ので、何もしないとキーボードが下がって投稿欄がカプセルに戻り、サムネイルの列が隠れて、閉じる画像の戻り先がなくなる
- 閉じる動きが終わってから、入力欄を最初の応答者に戻す。入力欄を最初の応答者のまま開くと、ビューアを閉じた時点でUIKitが入力欄にキーボードを戻し、シミュレーターでは閉じ始めの画像が約0.37秒止まった
- SciaCoreの`DraftAttachment`のほかに、アプリ側で`DraftAttachment.id`ごとに次を持つ
  - ピッカーの`assetIdentifier`との対応
  - 端末で作ったサムネイルと、手元のファイルの場所。前に選んだ写真は、ピッカーに渡しても`itemProvider`が空で返る（PhotosUIのヘッダーに明記）ので、ピッカーから読み直せない
  - 種類と縦横比（サーバーの応答より前から、セルの印とビューアの枠に使う）
  - アップロードの進み具合
  - 失敗の理由。`DraftAttachment.State.failed`は理由を持たないため、投げられたエラーを持っておく。再試行が待ち直しか送り直しかも、これで分かる
  - 代替テキストの送信が失敗したこと（`needsDescriptionUpdate`のまま止まるため、送り直す操作と表示が要る）
