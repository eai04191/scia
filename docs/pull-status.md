# 引っぱると見える新着の経路

タイムラインと通知の一覧を一番上からさらに引っぱると見える表示と、引っぱって離したときの読み直しで、作者が決めたこと。

- 新着が届く2つの経路を、ストリーミングとRESTの2列に分けて並べる。つながっていても、切れていた間をRESTで読む補完が終わるまで新着は出ないため、「つながっているのに新着が出ない」ときに、どちらで止まっているかが分かるようにする
- 列の中は左寄せで、見出し、アイコンと状態、小さな補足を縦に並べる。補足に収まらない、止まっている理由は、2列の下に出す
- ストリーミングの補足は、つながっている間の流速を「12件 / 分」と出す。その一覧に届いた新着の、直近1分の数
- RESTの補足は、読み終えたら時刻、読み込み中は読んだ件数、止まっている間は一覧がいつまでの投稿を出しているか（「8:36:27まで」）
- 読み込み中に、全体の数や「2/5」のような割合は出さない。何ページ読めば終わるかをサーバーが返さず、続けて読むページ数の上限は、たいてい途中で終わるので当てにならないため
- レート制限でサーバーに止められている間は、失敗ではなく「待機中」と出す。明けたら自動で読み直すため
- ギャップの行の読み込みは、行の中に出ているので、ここには出さない

## 引っぱって読み直す

- 投稿、通知、人を並べるどの一覧でも、一番上から引っぱって離すと最新の状態を読む。同じ操作がどの一覧でも効くよう、一覧を作るときに何を読むかを必ず決め、決めずに作るとビルドが通らないようにする
- 新しいものが上に来る一覧（ホーム、ローカル、連合、リスト、ハッシュタグ、通知、ブックマーク、お気に入り、プロフィール）は、一番新しいものより後に増えたものだけを読んで上に足す。全体を読み直すと、下まで読んでいた位置を失うため。足した行は、切れていた間の補完と同じく、読んでいる行を動かさずに入れる
- 足す分が多くて手元の一覧とつながらなかったら、手元の古い行を捨てずに残し、間にギャップの行を出す。下まで読んでいた位置を失わないため。ホーム、ローカル、連合、リスト、ハッシュタグは、ギャップの行を押したときと近づいたときに読む。通知、ブックマーク、お気に入り、プロフィールは、押したときに読む
- プロフィールは、アカウントと固定された投稿も読み直す
- スレッドと人の一覧は、新しいものが上に来る並びではないため、全体を読み直す
- 最初の読み込みに失敗したままの一覧では、引っぱるとそのやり直しになる
- 見た目はiOS標準の更新コントロールにし、読み終えるまで出しておく。補完の最中に引っぱったら、その補完と続きの読み込みが終わるまで待つ。溜めている新着は、間隔を待たずに入れる
- 引っぱっている間は、更新コントロールの下に経路の状態が見える。離して読んでいる間は、更新コントロールが一覧のすぐ上に止まって位置を変えられないため、経路の状態は出さない
