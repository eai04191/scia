# 引っぱると見える新着の経路

タイムラインと通知の一覧を一番上からさらに引っぱると見える表示で、作者が決めたこと。

- 新着が届く2つの経路を、ストリーミングとRESTの2列に分けて並べる。つながっていても、切れていた間をRESTで読む補完が終わるまで新着は出ないため、「つながっているのに新着が出ない」ときに、どちらで止まっているかが分かるようにする
- 列の中は左寄せで、見出し、アイコンと状態、小さな補足を縦に並べる。補足に収まらない、止まっている理由は、2列の下に出す
- ストリーミングの補足は、つながっている間の流速を「12件 / 分」と出す。その一覧に届いた新着の、直近1分の数
- RESTの補足は、読み終えたら時刻、読み込み中は読んだ件数、止まっている間は一覧がいつまでの投稿を出しているか（「8:36:27まで」）
- 読み込み中に、全体の数や「2/5」のような割合は出さない。何ページ読めば終わるかをサーバーが返さず、続けて読むページ数の上限は、たいてい途中で終わるので当てにならないため
- レート制限でサーバーに止められている間は、失敗ではなく「待機中」と出す。明けたら自動で読み直すため
- ギャップの行の読み込みは、行の中に出ているので、ここには出さない
