# プロモーション動画の素材

プロモーション動画の素材を、台本から自動で撮る仕組み。台本には、決まったタイミングでの操作と、起こすイベント（新着、通知など）を書く。外部依存はすべてモックにし、いつ撮っても同じ見た目と流れの動画を出す。XCUITestは1操作ごとにアプリが落ち着くのを待つので、操作の時刻は毎回少しずれ、フレーム単位では揃わない。

## 撮る

```bash
make promo SIM='<シミュレーターの名前>'
```

`Tools/promo-record.sh`が、台本のUIテストを走らせながら`simctl io recordVideo`で撮り、`DerivedData/promo.mp4`に出す。`SCENARIO=<テストのクラス>/<テストの名前>`で台本を、`OUT=<ファイル>`で出力先を変える。素材は1206×2622、一定の60fpsで、ステータスバーは9:41・電波と電池が満タン、外観はライトに固定される。

- 実機では撮らない。端末の画面全体を取り込むとXCUITestのオーバーレイ（Automation Running）が写り、アプリの中の録画（ReplayKit、`ScenarioRecorder`）は884×1920に縮んでステータスバーも写らない。実機の名前を渡すとReplayKitで撮る作りは残っている
- 撮影用のビルドは`Config/Promo.xcconfig`で、バンドルID（`net.mizle.scia.promo`）、表示名（Scia Promo）、URLスキームを変え、いつものSciaと並べて入れる
- UIテストは`AppUITests`のターゲット`SciaUITests`にあり、scheme`SciaPromo`だけで走る。`make test`には混ぜない

### 録画と切り出し

- 素材の範囲は、台本が画面全体に0.3秒出すマゼンタの目印（`ScenarioMarker`）を、録画の中から探して決める。台本の時刻やMacの時計では切り出さない
- `simctl`の録画は、画面がしばらく変わらないとその間の時間が消え、時計と合わなくなる。撮影モードのアプリは、画面の左上の隅の1ptを毎コマわずかに変え続けて、毎コマ書かせる（`ScenarioHeartbeat`）
- 切り出すときに一定の60fpsにそろえる。録画の時刻をそのまま持ち込むと、同じ時刻のコマが並んでカクついて見える
- sim-useの`record-video`は使わない。画面の更新と別の間隔で取り込むので、同じ絵を2回撮ったり飛ばしたりする
- シミュレーターでも、アプリの中の録画（`record-start`）は動く。送ると二重に撮って描画が重くなるので、シミュレーターでは送らない
- 録画に音とタッチの位置は入らない。音は編集で重ね、指の位置を見せるなら編集で丸を重ねる

### 滑らかさを確かめる

- コマの変化の大きさで数えない。ゆっくりした動きは1コマの変化が小さく、止まっていると取り違える
- 一覧の部分を切り出して、連続するコマの縦のずれ（px）を、行ごとの明るさの並びを重ねて求める。ずれが一定なら滑らかで、倍になったコマは1コマ落ちている。速い動きは、行の高さの半分を超えると取り違えるので、縮めすぎない
- アプリ自身の記録（`scroll timeline`のログの、落ちたコマの数と遅れの合計）と突き合わせる

## 台本「流れても、動かない」

`StreamingDemoUITests`（アプリ側は`StreamingDemoScenario`）。ストリーミングで新着が流れてきても、読んでいる位置が動かないことを見せる。約30秒。

1. 一番上にいるところに新着が3件流れ込む（`arrivals-top`）
2. 軽くスワイプして下へ読み進め、4枚の写真の投稿で止まる
3. 新着が5件届くが、読んでいる投稿は動かず、新着のボタン「↑5」だけが出る（`arrivals-reading`）。投稿の位置が0.5pt以上動いたら、テストを失敗させる
4. 1枚目の写真を開き、2枚目へ送る。開いている間にも新着が2件届く（`arrivals-viewer`）
5. 下へスワイプして閉じると、読んでいた位置に戻る
6. 新着のボタン「↑7」を押して一番上へ戻る
7. お気に入りの通知が届き、通知のタブで読む（`favourite`）

投稿は、架空の7人のアカウントが書いた20件と、新着の10件。アイコンと写真は端末で描いてdata URLにする。

### 撮る前の準備

目印を出す前に、次を済ませる。どれも、済ませないと素材でカクつく。

- ビューアを一度開いて4枚とも送り、閉じる。起動して最初に開くときだけ、準備で開く動きが止まる
- 一度下へスクロールして、一番上へ戻す。初めて出る行は、画像を読んで並べる分だけ、スクロールの途中でコマが落ちる

### 操作の送り方

- 読み進めるところは、短く速くスワイプして指を離し、慣性で流す（55pt、700pt/秒）。一定の速さでゆっくり動かして止めると機械的に見える。長くゆっくりスワイプすると、指を離す直前に一瞬止まり、慣性の前に止まって見える
- ビューアは、XCUITestでタップせず、アプリに合図して開かせる（`viewer?index=0`。サムネイルをタップしたのと同じ経路）。XCUITestでタップすると、タップのあとに画面の要素を読む間、開く動きが飛ぶ
- XCUITestのドラッグは、指の動きが1/60秒ごとにアプリに届く。次の方法は使わない
  - XCTestの非公開APIで指の動きの列をまとめて送る方法（WebDriverAgentと同じ）。シミュレーターでは時刻を守らず、一度に流れ込む
  - sim-useの`swipe`。指の動きが不ぞろいに届き、コマが落ちる

## 撮影モード

起動の引数`-scenario <台本の名前>`で、アプリを撮影モードで起動する（`ScenarioMode`）。Debugビルドで撮る。

- アカウント: Keychainを読まず、台本の`Credential`でタイムラインを出す。ログインがいらない
- RESTとストリーミング: `SessionController.init`の`FaultInjectingTransport`と`FaultInjectingWebSocketConnector`の`base`を、台本のサーバー（`ScenarioServer`）に替える。障害を起こすデバッグの操作は、台本の中でも使える
- 画像: data URLにする。`URLSession`はdata URLをそのまま読むので、画像の読み込みは替えない
- 設定とチューニング: 起動のたびに空にする別の`UserDefaults`（`ScenarioMode.defaults`）から読み、既定値で撮る。値を変えて撮るなら、ここに型どおりの値を入れる。XCUITestの`launchArguments`では渡さない。値が文字列で入り、数値と真偽値の項目は既定値のままになる
- デバッグメニューのボタンは出さない

台本で使う場面が出てきたら、次も差し替える。

- Xの投稿の囲み: `SessionController`の`XPostStore`は、`XPostClient(transport: URLSessionTransport())`を直に作っている
- 動画、GIF、音声: ビューアは添付ファイルの`url`から直に`AVPlayerItem(url:)`を作り、data URLは再生できない。同梱したファイルか端末で書き出したファイルの`file://`のURLにする

## 台本のサーバー

`ScenarioServer`は、台本（`ScenarioScript`）のJSONを返す。台本にないAPIには404を返し、`scenario`のカテゴリーのログに`scenario no response`と残す。台本を足したら、このログが出ないことを確かめる。

- 起動するとすぐ読むAPIに答える（`verify_credentials`、`accounts/<自分のID>`、`v2/instance`、`preferences`、`markers`、`custom_emojis`、`timelines/home`、`notifications`）。`preferences`と`markers`は、404だとその機能が止まる
- `markers`で読み始める位置を決める。ホームも通知も一番新しいIDにして、一番上から始め、通知のバッジも出さない
- ホームと通知は、Mastodonと同じく`max_id`、`since_id`、`min_id`、`limit`で区切って返す
- 投稿のJSONは、SciaCoreのモデルをエンコードせず、APIと同じ形の辞書から作る（`ScenarioFixtures`）。モデルのデコードは欠けた項目を補うので、エンコードし直してもAPIと同じ形にならない
- 本文にリンクを入れるなら、カードを最初から付ける。付けないと、カードが後から届く動きになる

## イベントを起こす

- 台本からアプリへの合図は、Darwin通知（`ScenarioSignals`）で送る。名前は`net.mizle.scia.scenario.<パス>`で、パスはデバッグURLのホストから後ろ（`scenario/arrivals-top`、`viewer?index=0`など）。Darwin通知は中身を運べず、名前を前もって登録する必要があるので、アプリは受け取るパスを並べて登録する（`ScenarioMode.signalPaths`）
- URLでは合図しない。URLを開くとアプリが一度切り替わり、ステータスバーに「◀ Scia」が出て写り、その間は動きが飛ぶ
- 台本のイベントは、台本のサーバーがMastodonのストリーミングと同じJSONで流すので、実物と同じ経路で新着が入る。既存の`dummy/<種類>`はストリーミングを通らないので使わない
- 新着は、アイコンを読み終えるのを待ってから挿入される。台本の新着は、一覧にいるアカウントだけが書く
- 指で触っている間は挿入を待つので、スクロールの最中に新着を流さない

## 時刻

- 投稿の時刻は、起動した時刻から「N分」ちょうどより1秒前にずらして作る。相対時刻は分の切り捨てなので、起動から1分以内に撮り終えれば表示が変わらない
- 日時の表示（`absolute`）で撮るなら、撮影モードの時計が要る。`StatusTimestamp`は日時でも今の時刻と比べて書き方を変えるので、`PostContentConfiguration`が渡している`.now`をその時計に替える。カードの取り直し（`LinkCardRefreshSchedule.note(_:now:)`）にも同じ時計を渡す

## 写真ピッカー

まだ台本に入れていない。`PHPickerViewController`は別のプロセスが描くので、モックにせず本物を使う。

- 撮影専用の端末をリセットしたあと、`xcrun simctl addmedia`で写真を入れる。あとから入れた写真ほど左上に並ぶ
- ピッカーの中の写真はXCUITestの要素として読めないので、並びから求めた座標を押して選ぶ
- 起動して最初に開くときだけ、表示まで数秒かかってばらつく。撮る前に一度開いておく

## 文字入力

まだ台本に入れていない。ソフトウェアキーボードのキーを押して打つと、キーのポップアップ、入力中のかな、変換の候補が録画に映る。`typeText`は使わない。

- 先に`make sim-keyboard SIM='<端末>'`でハードウェアキーボードを外す
- キーボードは前回使ったもので開くので、「次のキーボード」ボタンを目的のキーボードになるまで押す。ボタンの`value`は今と次のどちらを指すか分からないので、判定に使わない。日本語かなは「あ」のキーで、日本語ローマ字はQのキーと「改行」のリターンキーで見分ける。どのキーボードが入っているかは端末の設定による
- フリックは、XCUITestでキーの中心から`press(forDuration:thenDragTo:)`で上下左右に50pt動かす。濁点・半濁点・小さい文字は、identifierが「゛」のキーを押す。1入力に約0.4秒かかる
- 速く打つなら、sim-useの`ios batch`でキーの座標を続けてタップする。1打約0.22秒で、ポップアップも映る。sim-useは指を動かせないので、フリックはできない。台本に組み込むには、UIテストからMacのスクリプトに合図して、スクリプトがsim-useで打つ形にする
- 変換の候補は、候補の文字列をidentifierに持つセルとして並ぶので、タップで選ぶ
- 候補にその日の日付が出る（「きょう」なら「10/19」など）。Macの時計に従うので揃えられない。日付の候補が出ない言葉を選ぶか、候補の列を映さない。打った言葉の学習は端末のリセットで消す
