# FormとListの画面の作り

## FormとListの画面すべて

設定や通報のように、`Form`や`List`で作る画面に当てはまる。

- `Form`や`List`の行は、iOSの設定アプリに倣い、押せるかどうかを行の形で示す。名前と値の行は見るだけ、シェブロンの行はほかの画面へ入る、名前だけの行はボタンにする。ボタンの行には値を並べない。押せることを色だけで示すと、アクセントカラーのモノトーンで押せない行と見分けられなくなり、iOSの「ボタンの形」もこの行には効かないため
- 行全体が押せるボタンに確認（`confirmationDialog`）を付けるときは、ラベルを行の幅に広げ、行の真ん中から出す

## 設定の画面

- 説明の長い文を節の見出しやフッターに入れない。画面が何かやなぜ変えられないかのような説明は、節の中の行として書く（アカウントの画面の「外観」の1行目など）
- 項目が1つのセクションの見出しは、行の名前に情報を足すときだけ付ける（「ブースト」の見出しの「公開範囲」など）
- トップの分類は、見る（表示）、触る（操作）、書く（作成）の場面で分ける。アプリのアイコンはホーム画面のアイコンを変える設定で、範囲が違うので「表示」に入れない
